Presenter cheat sheet
Keys work only when armed (?present=1 or Ctrl+Shift+P) and not inside text fields. Every key also has a mouse control on the presenter bar. Source: RUN_SHEET.md, PRESENTER_KEYS.md

Keys

PStart: Stage on, step 00
SpaceNext step (failed step: retry)
→Skip to the next step
←Back one step
BFallback clip (again = live)
RReset, after a confirm: all demo sessions signed out, step 00
LEnglish / 简体中文
SStage theme on / off
DDeliverables: Leo, his panel (Esc: back to the previous person)
2Open citation 2 (Compare)
?Key help
EscClose a sheet or dialog; never hides the bar once started
HHide / show the bar

Mouse, same actions: ▶ Next = Space · ◀ Back = ← · ▷ Start = P · Recording = B · Reset the demo = R (same confirm) · Hide the bar = H · More = ? (Stage) · side buttons back / forward = ← / Space. Ordinary clicks stay ordinary.

Recovery ladder

  1. App stalls. Ishaan says the next line's first four words; Dev presses B (clip plays).
  2. Wrong state. Press R, then confirm: signs every demo session out and goes back to step 00. It restores nothing and never edits the real ledger (the tamper step only ever changes a copy).
  3. Network fails in the WorkBuddy beat. Play clip C and say in one clause that it is a recording.
  4. Running long. Cut in order: CodeBuddy line, Hy3 open-weight line, audit-row cut. Never cut the tamper or the identical refusals.
  5. Hy3 not live. Keep the default line: "quoted from the sources, with the same checks".

A recording is never presented as live. If a judge interrupts: one sentence, then "let me finish this step, then I will come back."
