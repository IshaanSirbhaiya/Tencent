Reviewed only the pasted code. Confluence, Slack, the directory implementation, ACL evaluator, index, and webhook consumers are absent, so their behavior cannot be verified. No Critical finding is established by this bundle.

1. **[High] Restricted Jira comments inherit the issue’s broader ACL** — `connectors/jira.py`, `_build_doc`, `check_access` — Every returned comment is included without checking its visibility restriction. A service account can fetch a restricted comment, and an ordinary issue reader can pass both gates and receive it. The comment about the generator not emitting restrictions does not enforce the supported subset against real Jira. **Fix:** Exclude restricted comments or index them separately with their own authorization checks; deny unsupported configurations.

2. **[High] Drive Gate 2 can authorize revoked group members** — `connectors/drive.py`, `check_access`, `compile_acl` — Gate 2 refreshes file permissions but evaluates group/domain membership using the supplied directory user. After removal from a Google group, its unchanged file grant still authorizes someone whose cached group membership is stale. Both gates can allow. **Fix:** Use authoritative, fresh membership for Gate 2, or a user-scoped source read. If membership freshness cannot be established, return `unverifiable`.

3. **[High] Default group mappings can grant unrelated directory groups** — `connectors/jira.py`, `__init__`, `_branch`; `connectors/drive.py`, `_default_group`, `compile_acl` — Jira assumes a native group identifier is already an IB group identifier; Drive assumes the email’s local part identifies the corresponding IB group. If these namespaces differ, `finance@companya.example` can grant an unrelated directory group named `finance`. Drive repeats this mapping in Gate 2. **Fix:** Require explicit, tenant-scoped mappings to stable native group identities. Unknown or ambiguous mappings must deny.

4. **[High] Missing Jira security information becomes “unrestricted”** — `connectors/jira.py`, `_meta`, `acl` — `_meta` treats an omitted `security` field, a malformed security object, and explicit `security: null` identically. An incomplete response for a restricted issue therefore compiles only Browse permission, over-granting Gate 1. Jira’s live check remains a backstop under the supplied semantics. **Fix:** Require the requested field to exist and validate its shape; only explicit, valid `null` should mean no security level.

5. **[High] Malformed Drive permission entries are silently discarded** — `connectors/drive.py`, `_permissions`, `compile_acl` — A permission list containing a valid user grant and a non-object entry is accepted after the malformed entry is dropped. The connector cannot establish whether that discarded entry represented an `anyone`, expiring, or unsupported permission requiring whole-file denial. Gate 2 uses the same parser. **Fix:** Validate every entry and required field before compilation; any malformed entry must invalidate the entire permission response.

6. **[High] Drive permission pagination can return an incomplete policy as authoritative** — `connectors/drive.py`, `_permissions` — After 10,000 pages, the method returns accumulated entries even if another page remains. A user grant in collected pages can authorize access while an `anyone` or unsupported permission on an omitted page should deny the whole file. A repeating pagination token can trigger the same condition. **Fix:** Detect repeated tokens and raise on exhaustion with a continuation token. Gate 2 must deny incomplete enumeration.

7. **[High] Adjacent card numbers leave later cards unmasked** — `sensitive.py`, `mask`, `_best_run` — For `4111 1111 1111 1111 4111 1111 1111 1111`, the PAN regex consumes both cards as one match. `_best_run` returns only the first accepted run, and `mask` never examines the rest of that match. The second card remains raw. This also disproves the claimed idempotence: another invocation can mask the remaining card. **Fix:** Enumerate all accepted, non-overlapping runs within each candidate, including its unprocessed suffix.

8. **[High] Common formatting and surrounding characters bypass PAN masking** — `sensitive.py`, `DEFAULT_RULES`, `mask` — Valid numbers such as `4111 1111 1111 1111` using nonbreaking spaces are missed. So are wrapped numbers split by newlines and contiguous numbers adjoining a word character or hyphen, such as `card_4111111111111111` or `-4111111111111111`. They reach the output unchanged. **Fix:** Recognize supported Unicode spacing and layout variations, and use context-sensitive boundaries that do not exclude common labels or punctuation. Preserve original offsets during normalization.

9. **[High] Source text can trigger cubic masking work** — `sensitive.py`, `_best_run` — A long candidate containing thousands of space-separated zeros makes the function examine quadratically many group ranges and reconstruct their strings. Most are far beyond `max_len`, but rejection happens after reconstruction, producing approximately cubic work. A document editor can stall ingest. **Fix:** Use bounded windows and accumulated lengths; stop extending a candidate once its maximum length is exceeded. Enforce input/work limits and quarantine documents when masking cannot complete.

10. **[High] Accepted rule configurations can disable masking or retain complete secrets** — `sensitive.py`, `load_rules`, `compile_rules`, `Rule.masked` — A version-1 configuration with missing or empty `rules` produces no masking. Negative retention counts and excessive `keep_head`/`keep_tail` values are accepted; a PAN rule with `keep_head: 19` preserves a complete PAN in both output and findings. Capture-group indexes are also unchecked until matching. **Fix:** Validate required protections, nonempty rule sets, capture groups, retention bounds, and guaranteed redaction at load time. Reject configurations that can preserve an entire accepted value.

11. **[Medium] Delivery-ID substitution bypasses webhook replay protection** — `connectors/_http.py`, `sign_webhook`, `WebhookVerifier.verify` — The HMAC authenticates timestamp and body, but not `X-IB-Delivery`. Someone possessing one valid delivery can replay its signed body within the timestamp window with unlimited different delivery IDs. Drive ACL events can repeatedly trigger expensive source traversal. This is replay, not arbitrary payload forgery. **Fix:** Authenticate the delivery ID, or deduplicate an authenticated timestamp/body digest as well as the ID.

12. **[Medium] Replay protection is local to one verifier instance** — `connectors/_http.py`, `WebhookVerifier.__init__`, `verify` — Even an unchanged delivery can be accepted once per worker or connector instance and again after restart. The lock protects only one in-memory dictionary. **Fix:** Use a shared atomic replay store with expiry covering the complete acceptance window and clock skew.

13. **[Medium] Webhook user resolution conflates native and directory identifiers** — `connectors/jira.py`, `_ib_user`; `connectors/drive.py`, `_ib_user` — Both functions first interpret a native-looking value as an IB ID. If native user `"123"` maps to Alice but IB ID `"123"` belongs to Bob, Alice’s revocation event targets Bob. Unknown identifiers also pass through unchanged. This can leave the intended user’s cached authorization stale; the consumer’s exact behavior is not shown. **Fix:** Define one explicit identity namespace per event field, resolve only through that namespace, and handle unresolved identities through conservative invalidation.

14. **[Medium] Directory remapping does not change ACL fingerprints** — `connectors/jira.py`, `list_changes`; `connectors/drive.py`, `perms_fingerprint`, `list_changes` — Fingerprints cover native policy values, but not the directory or group-mapping revision used to compile them. If a native account is remapped from Alice to Bob, the stored ACL can retain Alice without any source permission change. A complete external directory invalidation mechanism could mitigate this, but none is shown. **Fix:** Include mapping revisions in ACL dependencies and invalidate all affected documents when mappings change.

15. **[Medium] Failed folder expansion loses effective descendant invalidation** — `connectors/drive.py`, `_expand_acl_ids`, `_descendant_files` — On a lookup failure, an ACL event for a folder becomes an event for `drive:<folder>`. The connector indexes files, so this fallback does not identify the descendants whose ACLs need refreshing. Current-tree traversal also cannot identify descendants that have already moved away. **Fix:** Combine stored and current descendant sets; retain pending invalidation on failure or invalidate the containing drive conservatively. Fresh Gate 2 checks remain a backstop.

16. **[Medium] The PAN issuer filter excludes valid card ranges** — `sensitive.py`, `DEFAULT_RULES` — The prefix expression rejects legitimate Maestro ranges starting with `50` or `56`–`59`, even when the length and Luhn check pass. These cards remain raw. **Fix:** Use a maintained issuer-range model or conservatively mask all qualifying Luhn-valid candidates, accepting the corresponding false-positive tradeoff.

17. **[Medium] Lowercase and common formatted identity values escape detection** — `sensitive.py`, `DEFAULT_RULES`, `mod97_valid`, `nric_valid` — The IBAN and NRIC regexes are uppercase-only. Lowercase values never reach validators that could normalize their case. Nonbreaking spaces in IBANs similarly prevent detection. **Fix:** Normalize case and supported formatting before validation while retaining an original-span mapping.

18. **[Medium] Configurable regular expressions permit catastrophic backtracking** — `sensitive.py`, `compile_rules`, `mask` — Configuration accepts unrestricted Python regular expressions for both candidates and prefixes. A pattern such as `(a+)+$` can make matching adversarial document text take exponential time. This requires an unsafe rule configuration; it is separate from the default rules’ cubic scanning defect. **Fix:** Restrict the rule language or use a bounded/linear-time matcher, plus document-level execution limits.

19. **[Medium] Masking omits other document string fields** — `sensitive.py`, `mask_doc`; connector `_build_doc` methods — Only `title` and `text` are masked. A Drive/shared-drive name or Jira project name containing a PAN remains raw in `container_name`. Raw values can also survive in other metadata. Whether those fields reach the index or citations depends on omitted code. **Fix:** Apply field-aware redaction to every indexed, logged, displayed, or model-visible string; define explicit handling for identifiers and URLs.

20. **[Medium] Gate 2 lacks the advertised hard overall deadline** — `connectors/_http.py`, `request_gate2`; `connectors/drive.py`, `_permissions`, `check_access` — Passing an HTTPX timeout does not impose a total authorization deadline. Drive can make thousands of sequential permission requests, each with a fresh timeout; incremental response activity can also extend elapsed time. This is an availability defect, not a demonstrated allow-on-timeout. **Fix:** Enforce a monotonic deadline for the entire Gate 2 operation, with strict page and response-size limits.

21. **[Low] Weak semantic validation causes avoidable false positives** — `sensitive.py`, `DEFAULT_RULES`, `mod97_valid` — NRIC masking explicitly uses `validate: none`, so any matching shape is redacted despite the available checksum validator. IBAN validation checks mod-97 without validating the country and its required length. Unrelated Luhn-valid numeric identifiers can also be classified as PANs. **Fix:** Validate IBAN country/length structure, make the NRIC checksum policy explicit, and use context where false positives materially harm content. Document deliberate conservative masking.

What is correct:

- Jira compiles Browse permission **AND** issue security, with supported holders combined using OR. Under the supplied semantics, its admin permission check provides the intended issue-level Gate 2.
- Both connector Gate 2 implementations deny caught transport failures, timeouts, rate limits, malformed JSON, and unexpected exceptions. No exception-to-allow path is demonstrated here.
- The Gate 2 request helper contains no retry loop; ingest retry behavior is separate.
- Drive denies `anyone`, expiring permissions, unknown permission types, and unknown roles when those entries reach the compiler. Foreign-domain grants contribute no access.
- Under the supplied `permissions.list` semantics, Drive consumes effective inherited entries rather than independently adding ancestor grants.
- Webhooks verify HMAC and timestamp before parsing events or performing Drive lookups. Signatures use constant-time comparison. The shown code emits change events rather than directly applying payload ACLs.
- Drive takes its initial change token before listing files and considers both old and new folder trees during incremental invalidation.
- For accepted default-rule matches, findings omit raw values, and Luhn/mod-97 validation reduces accidental matches.
