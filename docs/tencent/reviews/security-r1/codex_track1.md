Reviewed only the pasted bundle; no tools, files, or browsing. Locations below use exact file and function names. P4 and P6 were not defined. Connector implementations, `grounding.py`, ledger/storage implementations, and injected routers were not supplied, so their guarantees cannot be verified.

1. **[Critical] Demo login permits unauthenticated impersonation when enabled** — `databridge_ib/app.py`, `create_app.demo_login` — Anyone can submit a known administrator or compliance officer’s persona and receive an eight-hour signed session. Signing the token does not repair the attacker-controlled identity selection; this defeats P8 in any accessible deployment with `demo_login=True`. **Fix:** Exclude this endpoint from production builds/startup, isolate demos with synthetic data, and use authenticated identity-provider assertions for real sessions.

2. **[High] Service-account read-through can release newly restricted content** — `databridge_ib/pipeline.py`, `Pipeline._read_through`, `_select` — Gate 2 approves version V1; access is then revoked or V2 becomes restricted. `conn.fetch(d)` retrieves V2 with service credentials, and `conn.acl(d)` can return a policy denying the user. The code nevertheless adds `d` to `ok`, and `_select` explicitly unions it into the search pool. V2 can enter the model, violating P1. **Fix:** Fetch under the principal or obtain a source-bound authorization/content snapshot; validate document identity, version, and current permission after fetching. Never unconditionally admit refreshed documents.

3. **[High] Authorization is not bound to the content actually sent or released** — `databridge_ib/pipeline.py`, `Pipeline.ask`, `_passages`, `_citation`; `databridge_ib/index.py`, `Index.doc`, `search` — Gate 2 checks a document, then ingestion can replace its content or ACL before reranking or passage construction. Revocation during model generation is also never checked before release. Old hit text can be paired with a newer, potentially restricted title, container, or version. **Fix:** Carry immutable, versioned evidence snapshots through retrieval and citations; revalidate relevant identity/ACL generations before model submission and release. Define a source-supported authorization linearization point—local rechecks alone cannot eliminate every remote race.

4. **[High] Source-revoked content still affects ranking and refusal decisions** — `databridge_ib/pipeline.py`, `Pipeline.ask`, `_select`; `databridge_ib/index.py`, `Index.search` — If source access is revoked before the query but indexed ACLs lag, the document contributes to IDF, average length, maximum lexical score, anchor availability, and top-K selection before Gate 2 denies it. Adding such a document can crowd out an accessible answer or change relevance thresholds. `_select` retains these denied documents in `readable` when recomputing scores. This violates P2 even when Gate 2 prevents passage disclosure. **Fix:** Compute ranking statistics and candidate limits over a source-current authorized corpus; remove denied documents and recompute selection, with an explicit design for stale ACLs throughout the corpus.

5. **[High] Token revocation fails open and concurrent revocations can disappear** — `databridge_ib/auth.py`, `load_revoked`, `revoke` — Missing, unreadable, or malformed JSON becomes an empty revocation list. `revoke` overwrites the file without atomic replacement or locking: readers can observe truncated JSON, and simultaneous writers can lose each other’s revocations. Previously revoked stolen tokens become usable. **Fix:** Use transactional revocation storage; fail authentication closed when revocation state is unavailable. Validate the stored schema and make updates atomic and concurrency-safe.

6. **[High] Logout does not invalidate the session token** — `databridge_ib/app.py`, `create_app.logout` — Logout only deletes the browser cookie. A copied cookie or bearer token remains valid for up to eight hours. Bearer authentication also takes precedence, so logout can authenticate one token while merely deleting another cookie. **Fix:** Retain verified session claims in the authentication context and revoke the authenticated `jti` before reporting successful logout; define behavior when both credentials are present.

7. **[High] Session cookies lack the Secure attribute** — `databridge_ib/app.py`, `create_app.demo_login` — `set_cookie` omits `secure=True`. If the deployment is reachable over HTTP, the browser may transmit the bearer-equivalent cookie unencrypted. `HttpOnly` and `SameSite` do not prevent that. **Fix:** Set Secure cookies and enforce HTTPS; use a suitably scoped host-only session cookie.

8. **[High] User-change webhook payloads directly disable users without source verification** — `databridge_ib/ingest.py`, `Ingestor.apply_event` — Every `user.changed` event becomes `set_active(ev.user, False)`. A legitimate profile update disables an active user, and subsequent activation events still disable them. This contradicts the stated “payload is never treated as truth” contract. **Fix:** Re-fetch the authoritative user record, apply its actual status and attributes, and audit the directory change.

9. **[High] Membership changes do not refresh cached principal membership** — `databridge_ib/ingest.py`, `Ingestor.apply_event`; `databridge_ib/directory.py`, `Directory` — `membership.changed` recompiles document ACLs but never updates `DirectoryUser.groups` or bumps the directory epoch. A removed group member remains Gate-1-readable; a newly added member can remain permanently excluded before Gate 2. Accurate native Gate 2 can prevent direct disclosure, but stale membership still breaks P2 ranking and demo correctness. **Fix:** Refresh affected users and transitive memberships atomically, rebuild relevant indexes, and increment the directory epoch.

10. **[High] Hanging access checks can exhaust the shared authorization pool** — `databridge_ib/gates.py`, `_POOL`, `check_all` — `Future.cancel()` cannot stop an already-running connector call. Sixteen hung checks consume every worker; subsequent requests queue more work and time out. The queue is unbounded, and this module imposes no connector-level transport timeout. **Fix:** Enforce network deadlines inside connectors, bound outstanding work, apply backpressure and per-source concurrency limits, and isolate persistently failing sources.

11. **[High, conditional] Embedding calls can bypass the write-ahead model boundary** — `databridge_ib/index.py`, `Index.search`, `upsert`; `databridge_ib/pipeline.py`, `Pipeline.ask`, `_read_through` — With a remote/model-backed custom embedder, query embedding happens before `retrieval.decided`; read-through also embeds fetched passage text before that event. Ingestion embeds documents without any asker authorization context. This violates the literal “before any model call” P5 claim and can expose read-through content from finding 2. The default offline embedder avoids the remote-disclosure case. **Fix:** Explicitly define whether embedding is inside the P1/P5 boundary. If it is, authorize and journal before dispatch; otherwise document and isolate its separate trusted processing boundary.

12. **[Medium] Global source status exposes activity outside the caller’s permitted corpus** — `databridge_ib/app.py`, `create_app.sources` — Every active authenticated user can see global ingestion/event timestamps, state, lag, and SLO status. Activity affecting only inaccessible documents changes this response, violating P2’s caller-visible noninterference claim. **Fix:** Restrict operational status to an appropriate role, or expose only caller-scoped information that does not depend on inaccessible activity.

13. **[Medium] Link resolution probes restricted objects before checking readability** — `databridge_ib/pipeline.py`, `Pipeline._resolve_link`, `_linked` — An accessible passage links to raw identifier `ABC-123`, and readable `confluence:ABC-123` exists. Adding inaccessible `jira:ABC-123` makes `_resolve_link` choose Jira first; `_linked` then rejects it without trying Confluence. The accessible answer changes solely because a restricted document exists. **Fix:** Resolve exclusively within the readable set, preferably using explicit platform-qualified identifiers.

14. **[Medium] Readable-cache keys omit an attribute used by ACL evaluation** — `databridge_ib/index.py`, `Index.readable`; `databridge_ib/acl.py`, `allows` — Domain ACLs depend on `user.email` through `user.domain`, but the cache key omits both. Two principal snapshots with the same keyed fields and epoch but different domains reuse the same readable set. The provided directory has no email-update API, so exploitation requires such a principal update or direct caller; the cache contract is still incomplete. **Fix:** Include all policy-relevant attributes or key on an immutable, guaranteed-to-change principal authorization version.

15. **[Medium] Grounding at the coordinator accepts any answer containing one valid citation** — `databridge_ib/pipeline.py`, `Pipeline.ask` — The acceptance condition allows arbitrary uncited assertions and nonexistent citation tags as long as one valid tag appears anywhere. For example, an unsupported claim followed by a supported sentence citing `[C1]` passes this check. Whether the normal chain prevents it depends on the omitted `GroundedNarrator`; this bundle does not establish an end-to-end P7 violation through that wrapper. **Fix:** Enforce sentence-level evidence binding at the coordinator boundary and fall back on any unsupported output. Preserve actual grounding/drop results rather than setting `dropped=0`.

16. **[Medium] Citation neutralization excludes source-controlled metadata** — `databridge_ib/narrate.py`, `Passage.line` — Only passage text is normalized and neutralized. A title or container name containing a newline and `[C2]` can forge another context line or citation-shaped boundary, undermining the declared one-line context contract. Instruction-bearing metadata also enters the prompt unchanged. **Fix:** Normalize and neutralize every source-controlled field; serialize evidence with unambiguous boundaries and keep citation binding independent of source-authored strings.

17. **[Medium] Material drift without a version is treated as usable cached content** — `databridge_ib/models.py`, `AccessCheck.allowed`; `databridge_ib/pipeline.py`, `Pipeline._read_through` — `AccessCheck(verdict="drift_material", current_version=None, ...)` is valid and allowed. Because refresh requires a truthy differing version, the pipeline releases old cached content despite an explicit material-drift result. A fetched version is also never checked against the reported source version. **Fix:** Require a trustworthy content version for verified release; treat incomplete drift results as unverifiable and verify the fetched snapshot.

18. **[Medium] Gate 2 can accept results completed after its advertised deadline** — `databridge_ib/gates.py`, `check_all` — After waiting on one future until the batch deadline, later `result(timeout=0)` calls still return successfully for already-completed futures—even if they completed after the deadline. No completion timestamp or freshness validation exists. **Fix:** Track submission/completion deadlines explicitly and reject late results; validate authorization-result freshness.

19. **[Medium] Index mutations are not rollback-safe** — `databridge_ib/index.py`, `Index.upsert`, `set_acl`, `delete` — Mutations alter in-memory state before committing SQLite changes. An insertion, vector conversion, or commit failure can leave partial memory state, an open transaction, and readable caches that were never invalidated because `_bump()` was not reached. Later operations may commit leftover changes. **Fix:** Stage and validate complete replacements, use explicit transactions with rollback, publish memory state only after successful commit, and handle failures without retaining inconsistent caches.

20. **[Medium] Concurrent index reads can fail or produce inconsistent evidence** — `databridge_ib/index.py`, `Index.search`, `doc`, `doc_ids`, `docs_in_container`; `databridge_ib/pipeline.py`, `_passages`, `_citation` — Search releases its lock after collecting chunks, then consults mutable `_docs` for time boosts. Concurrent deletion can raise `KeyError`; passage/citation construction can dereference `None`. Container iteration can race dictionary mutation. These produce intermittent 503/500 responses during normal ingestion. **Fix:** Return immutable snapshots captured under the lock and avoid rereading mutable document state later in the request.

21. **[Medium] Ingestion and read-through can overwrite newer state with older content** — `databridge_ib/ingest.py`, `Ingestor.sync`, `apply_event`; `databridge_ib/pipeline.py`, `_read_through`; `databridge_ib/index.py`, `Index.upsert` — The ingestion lock does not cover pipeline read-through. Two operations can fetch different versions, complete out of order, and unconditionally install an older document or ACL last. Index locking serializes writes but does not establish freshness. **Fix:** Coordinate updates per document and use source-version-aware conditional publication or generation checks.

22. **[Medium] Deletion events trust stale payloads and can remove restored documents** — `databridge_ib/ingest.py`, `Ingestor.apply_event` — `content.deleted` immediately deletes supplied IDs without source confirmation, delivery deduplication, or ordering checks. A delayed deletion event arriving after restoration removes a currently existing document. `delivery_id` and `at` do not protect application ordering. **Fix:** Reconcile current source state or apply source-supported version/tombstone ordering and idempotency.

23. **[Medium] Webhook handling lacks visible resource bounds and blocks the event loop** — `databridge_ib/app.py`, `create_app.webhook` — The endpoint buffers the entire body before verification, then runs synchronous fetching, embedding, indexing, and ledger work directly inside an async handler. Large requests or slow valid events can consume memory and block other requests. No application-level size or admission limits are shown. **Fix:** Bound request size before buffering, enforce source-specific verification, and hand verified work to a bounded durable worker queue. Signature/replay validation inside `parse_webhook` cannot be assessed from this bundle.

24. **[Medium] Raw ingestion exceptions can leak sensitive data into logs** — `databridge_ib/ingest.py`, `Ingestor.sync_all`, `_ledger_event` — Both log exception text with `%s`. Connector/storage exceptions can include URLs, credentials, response bodies, or content. The ask/model handlers already avoid this by logging exception class names. **Fix:** Log sanitized structured error codes and approved metadata; redact any diagnostic payload before sending it to a separately controlled sink.

25. **[Medium] Ingestion can report success despite failed security-change journaling** — `databridge_ib/ingest.py`, `Ingestor._ledger_event`, `apply_event`, `sync` — State and cursors are committed before audit append, and append failures are swallowed. A webhook can return 204 after an ACL or membership change whose audit event was lost. This is an audit-integrity defect; the narrowly stated ask-path P5 ordering is a separate matter. **Fix:** Use a transactional outbox or durable event acceptance record and retry journal publication without acknowledging untracked changes as fully processed.

26. **[Medium] Route allowlisting is documentation only** — `databridge_ib/app.py`, `create_app`, `ALLOWED_PREFIXES`, `mounted_paths` — The allowlist is never enforced. Injected audit/simulation factories can mount arbitrary paths or unauthenticated sensitive handlers; passing dependency helpers does not force their use. No such exposed handler is demonstrated because those factories are omitted. **Fix:** Validate mounted routes at startup and enforce sensitive-route authentication/authorization through mandatory router dependencies or an explicit endpoint policy.

27. **[Medium] Malformed tokens can escape the intended 401 handling** — `databridge_ib/auth.py`, `verify`, `load_revoked`; `databridge_ib/app.py`, `principal_dependency.current` — An unsigned header such as `Bearer x.é` reaches `hmac.compare_digest` with non-ASCII text and raises `TypeError`, which is not converted to `TokenError`. Signed non-object claims and invalid revocation-file shapes also trigger uncaught type errors. **Fix:** Validate token encoding and length before comparison, compare decoded signature bytes, validate claims and revocation schemas strictly, and map invalid credentials consistently to 401 while treating unavailable revocation state as an authentication-service failure.

28. **[Medium] Relevance filtering happens after top-K truncation** — `databridge_ib/index.py`, `Index.search`; `databridge_ib/pipeline.py`, `Pipeline.ask`, `_select` — Search returns its top K including `lexical=False` hits; the pipeline discards those afterward. High-scoring irrelevant chunks can occupy every slot while genuinely relevant chunks sit just below the cutoff. `_select` repeats this problem and truncates before per-document caps; its `hits` argument is unused, so platform-recall candidates can disappear. **Fix:** Apply relevance before top-K and enforce document/platform diversity during candidate selection, preserving the intended recall candidates.

29. **[Medium] Numeric time expressions can make ordinary questions unanswerable** — `databridge_ib/index.py`, `anchors`, `query_terms`, `Index.search`; `databridge_ib/timewin.py`, `parse` — For “What failed in the last 30 days?”, `30` remains a query term and an anchor. If no permitted chunk contains `30`, the whole clause becomes unanswerable despite matching incidents in the parsed window. Similar problems affect capitalization-based anchors in natural questions. **Fix:** Remove parsed temporal/routing spans before content relevance and anchor analysis; distinguish actual named entities from formatting and question wording.

30. **[Medium] Nested memberships declared on users are not expanded** — `databridge_ib/directory.py`, `Directory.from_world`, `_expand_groups` — If a user’s own `groups` contains a child group, but the child’s `members` list does not separately contain that user, ancestor groups are never added. The comment promising ancestor membership is therefore false for one supported representation. **Fix:** Normalize user-declared and group-declared memberships into one graph before transitive expansion.

31. **[Low] Platform hint matching is prefix-based rather than word-based** — `databridge_ib/pipeline.py`, `platform_hints` — The search for `" file"` also matches “filesystems,” `" chat"` matches “chattering,” and `" status"` matches “statuses.” Unintended platform searches can alter evidence selection and add work. **Fix:** Use token/phrase boundaries and normalize intended inflections explicitly.

32. **[Low] Extractive fallback is not always verbatim and can alter meaning** — `databridge_ib/narrate.py`, `extractive_answer` — URL removal rewrites sentences. “Do not use https://old.example; use https://new.example.” can become an incomplete or misleading instruction while retaining a valid citation. Tag neutralization also means the “verbatim” claim is not literally true. **Fix:** Preserve meaningful source text, or reject sentences whose sanitization removes essential content.

33. **[Low] Chunk size is not a hard limit** — `databridge_ib/index.py`, `chunk_text`; `databridge_ib/narrate.py`, `build_context` — A single long line or paragraph remains arbitrarily large. Fourteen passages therefore do not impose a context budget; one accessible document can trigger oversized embedding/model requests and failed demo answers. **Fix:** Split oversized individual paragraphs and enforce a total token budget before embedding and generation.

34. **[Low] Citation freshness and fallback metadata can mislead callers** — `databridge_ib/pipeline.py`, `_citation`, `EXTRACTIVE`; `databridge_ib/models.py`, `Citation`, `ModelInfo` — `stale` is never computed and always defaults to false. Read-through labels content checking with the earlier authorization timestamp. Extractive fallback after model failures still reports `fallback_used=False`. **Fix:** Track actual content-fetch times, compute staleness from a defined freshness policy, and preserve fallback provenance.

35. **[Low] Failure-stage auditing is absent and response serialization sits outside the 503 guard** — `databridge_ib/app.py`, `create_app.ask`; `databridge_ib/pipeline.py`, `Pipeline.ask`; `databridge_ib/models.py`, `RequestFailed` — Pipeline failures generate only an exception-class log, despite a defined `RequestFailed` event. Operators cannot distinguish retrieval, storage, or model failures from ledger history. Serialization after the `try` can also fail as an uncaught 500 after `answer.released` was appended. **Fix:** Record sanitized stage-specific failures when the ledger is available, prepare/validate the response before release journaling, and include serialization in controlled error handling.

Things that are correct in the supplied code:

- The ordinary authentication path derives identity from a verified token subject and resolves current active status and roles from the directory.
- Bearer-over-cookie precedence is explicit. An invalid bearer token does not silently fall back to a valid cookie.
- `AskRequest` forbids extra fields, including body-supplied identity.
- Tokens use HMAC-SHA256, constant-time signature comparison for valid encodings, an audience check, expiration checking, and bounded lifetimes when minted.
- ACL parsing fails closed; inactive users, unknown expressions, excessive nesting, and empty conjunctions do not grant access.
- For a fixed, accurate readable set, ranking statistics and vector comparisons use only that set. Time/platform preferences do not independently bypass access checks.
- Linked documents normally receive both readable-set filtering and their own Gate 2 checks.
- Gate 2 denies missing connectors, raised errors, invalid result types, mismatched document IDs, and observed timeouts.
- The main ask path appends `request.accepted` before retrieval, `retrieval.decided` before answer generation, and `answer.released` before returning. Raised ledger failures abort the pipeline and normally become generic 503s.
- Refusals use one constant text and suppress citations; Gate 2 reason codes are not directly returned to askers.
- Passage-body citation tokens are neutralized, and the system prompt explicitly treats source instructions as untrusted.
- API documentation routes are disabled, history queries are scoped to the authenticated user, and ask/model failure logs omit raw exception messages.
- Cursor advancement occurs after batch application and uses temporary-file replacement.
- Webhook parsing precedes event application, but cryptographic verification and replay protection depend on omitted connector code.
