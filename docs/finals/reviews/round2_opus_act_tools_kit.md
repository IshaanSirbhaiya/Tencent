## Verified safe (as far as checked)

- **Act identity**: every `/ib/act/*` body is a closed schema (`extra="forbid"`) with no identity field. The person always comes from `current` (token or cookie, then directory, then `active`), and `_employee` gates every route (`app.py:63-84,478-505`).
- **Act ownership and sealed answer**: `projection.owns(req_id, sub)` runs before `reconstruct`. `sub` and `status == released` are re-checked, and the stored answer must match `req_id`, be `intact`, and hash to the sealed `answer_sha256`, or it is a 503 (`actions.py:270-281`).
- **Act live re-check**: the cited documents go through `authz.authorize` (Gate 1 + live Gate 2) at draft and propose time. A sentence is kept only when ALL its tags are openable now, and none left means the one 404 (`actions.py:293-299`).
- **Act not-found**: one 404 for unknown, someone else's, refused, failed and revoked, recorded without the requested id (`actions.py:256-260`).
- **Act proposals**: owner-bound and single-use, marked under a lock (no double-confirm race), with a 15-minute TTL. They are released only on a validation error or a ledger failure before anything happens (`actions.py:443-457,466-479`). `project` must be in the live-checked closed set, and the summary is one line of 1..200 characters.
- **Act write-ahead**: `action.proposed` is appended before the draft or proposal is returned, `action.confirmed` before the create, and a ledger error is a 503 with nothing done. The ledger holds a digest, never the draft text (`actions.py:359-364,413-417,472-479`).
- **Act confirm**: the create permission is re-checked live at confirm, and the model never picks the project, recipient or action. The approved-script reply skips the model entirely.
- **Model draft output**: our code keeps only sentences whose tags are a subset of the context's tags, and drops sentences addressed to an AI (`actions.py:329-332`). This is not a value-level check; it relies on `ModelChain.draft`'s grounding wall, which I did NOT verify.
- **Sub-reviewer**: `hy3_check.py` never prints the key. The `demo_up.sh` env guard refuses to start without `.env.ib.local`. `make_files.py` is safe (no XML parser, no outside zips). `check_absent.py` uses loopback only and never prints the passcode. `assemble_finals.py` and `record_finals.cjs` have no shell injection (list-form subprocess, fixed scene list). `build_handouts.mjs` makes no remote fetch. The evidence outputs contain no tokens or keys (grep for `eyJ`, `Bearer`, `sk-`, key assignments and set-cookie). The `/api/walnut` proxy is off unless `WALNUT_PROXY=1` and not deployed, GET only, allowlisted, with a server-side token. The IB proxy's new routes are main-session only, and the 7 MB cap applies only to `sim/upload-file`. Presenter keys need arming and are ignored in inputs.
