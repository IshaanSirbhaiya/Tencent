## Verified OK

- **Session queue** (`components/presenter/session.ts`). `serialSession` never breaks the chain: each failure is caught and the next item still runs. `claimSession` counts the claim at click time, so a warm-up already running stops at its next `taken()` check. The warm-up and D put the previous person back only when `borrowed && owner unchanged`. R marks the session owned inside its queued step. A step's `signInMain` throws `SessionTaken` instead of overriding a shell change. `Providers.tsx` Sign out and persona switch both go through `claimSession`. Compare slots use their own cookies and stay outside the queue, which is correct.
- **Mouse and bar controls** (`PresenterBar.tsx`, `controller.ts`). Each control calls the same function as its key (`advance`, `goBack`, `startOnce`, `toggleClip`, `askReset`, `toggleHidden`, `exitPresenter`). Next uses `aria-disabled` and its click is guarded. Space on a focused bar button is swallowed on keyup, so a press never fires twice. Focus moves Hide → handle → Hide (it opens the More row in Stage). Side buttons are cancelled on mousedown, mouseup and auxclick, and a popstate within 1 s of a side button is ignored. No `data-testid` is duplicated in either layout.
- **B over a sheet**. The synthetic Escape reaches Radix's document-level listener. The presenter's own window-capture handler sees it with a dialog open and returns, so there is no recursion. The reset confirm is never closed this way.
- **Ready gates for steps 05 and 06**. `verify-status` and `[data-testid="verify-panel"] [role="alert"]` exist in `VerifyPanel.tsx:115,121`. `tamper-panel[data-state=done|error]` exists in `TamperDemo.tsx:197-198`. Auto-run happens once per mount, so a revisit shows the earlier, valid result and is never ready early.
- **11-step stage path**. `STEPS` is still 11 entries. Only the actions of `verify`, `tamper` and the grow timeout changed.
- **Recorder selectors**. Every test id the recorder uses in scenes 17, 18 and 21 still exists (`act-*`, `deliver-*`, `deliver-tab-${k}`, `starter`, `graph-left-add*`). For scene 19 the ids exist (`graph-main-addsheet-file`, `-picked`, `-folders`, `-upload`, `-upload-status`); only the persona is wrong (#1).
- **Rule 4 in the new copy, EN and zh**. Login notes are role-only in `personas.ts` and `PERSONA_ZH`. The folder hint names nothing. "No folder you can add files to was found." gives no reason. The blocked-ticket sentence says "from this answer". The 429 message gives no counts. The folder picker lists only folders the server returns, and the mock list mirrors `world.json`'s writer grants (admin sees all). Every starter swap is a manifest question for that persona (`user.spec.ts`).
- **ActSheet**. `failOf` maps 409 + `outcome_unknown` to "unknown" on propose and confirm, and 429 to "rate". The blocked header and description reset when the mode changes. "Draft a reply" switches the sheet in place, and focus returns to the opener on close.
- **Models, ledger and stats**.
  - `action.requested` is in `EVENT_KINDS` (`models.py:197`) and in the ledger's `_MODELS` (`ledger.py:73`). `ActionRequested` uses `EventBase.req_id`: `None` on `accepted`, the answer's id on `decided` and `replayed` (`actions.py:614,622,665,836`).
  - The new `GraphViewed` literals only widen the type.
  - `DeliverableRequested.export_format` is optional with a `None` default. Verify hashes the stored raw records (`DecisionLedger.read(raw=True)`), not a fresh `model_dump`, so rows written before this change still verify.
  - No kind collides. `stats.py` leaves export write-ahead rows out of `deliverables_requested`. `actions_requested` is counted but not exposed, and `kinds` counts it, which matches `backend_v1.md`.
- **Proxy**. `GET sim/upload-folders` is on the main-session allowlist only (`SLOT_ALLOWED` leaves it out, so a slot gets a 404). On `ib/open/<32 hex>`: if the browser sends any Sec-Fetch header, the link needs Dest `document`, Mode `navigate` and User `?1`. With none at all (curl, tests), it falls through to the Brain. Other GETs keep the same-site rule.
- **Preflight board**. It is served only on a loopback Host plus an IB-confirmed `whoami` (the mock's in mock mode, with a 5 s timeout), and is a 404 when `IB_DEPLOYED=1`. `demo_preflight.py` checks it as Maya after sign-in, and only as a warning. `demo_day.ps1` no longer probes it signed out (that probe would have forced a rebuild on every Start), and Start does not open the board.
- **`demo_day.ps1`**. The sign-in body is built with `ConvertTo-Json -InputObject @{…} -Compress` and sent as UTF-8; Windows PowerShell 5.1's `\u` escapes are valid JSON. The rest of the one-click path is unchanged. Note: `Test-SignIn` and `demo_preflight.py` read `IB_DEMO_PASSCODE` from the PowerShell environment, not from the key file. This was already so before this round. If the passcode lives only in `.env.ib.local`, Start says "cannot sign anyone in", so keep the passcode unset or put it in the environment too.
- **`demo_up.sh`**.
  - The PID 0 filter is `$5 != "0"` on LISTENING rows.
  - The `--fresh` refusal loop is safe under `set -euo pipefail`: a failing command substitution inside `[ ]` does not trip `-e`. It exits 4 before anything is wiped.
  - `envfile_get` handles a BOM, CRLF, `export` and quotes, and never runs the file as shell code. Its limits are in #2.
  - The seeder gets `IB_REPLAY_KEY` and `IB_VAR` (exported globally) plus the passcode and `MOCK_ADMIN_TOKEN`. In HTTP mode that is all it reads.
- **SECURITY §15.11-15.14 against the code**. These match the code: the `action.requested` stages and their `req_id`, the invalid confirm ledgered before its 422, the first-only rate rows, the one-create-at-a-time lock, the `/ib/open` 404-on-error and its 30-a-minute limit, the B9 WRITE re-check before the Drive write, B8 (no ledger is a 503), the B11 `.xlsx` extent check, the B13 capped download, the B2 `checking` poll row, the B1-B6, B12 and B14 deliverables items, and the 15.15 web and kit items.
