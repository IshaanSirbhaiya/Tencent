## Verified OK (Codex, static inspection; [checked] items also seen by the Claude seat)

- **Act identity.** Act request bodies forbid extra fields, and the user comes only from the verified session (`app.py:65-86, 103-120, 487-513`).
- **Confirm-time source re-check (round 2 Codex #3 fixed).** Every proposal source must still be openable for the confirming person, then Jira create is re-checked live (`actions.py:710-734`) **[checked]**.
- **Same-proposal retries (round 2 Codex #1, backend).** `_claim` moves pending to in-flight under a lock. In-flight and unknown proposals never create twice, and a created result is replayed (`actions.py:614-628, 679-688`).
- **Eviction (round 2 Codex #8 fixed).** In-flight and unknown proposals are never evicted inside their hold (`actions.py:585-603`).
- **Create outcomes.** A timeout, 5xx or malformed success is treated as unknown, and a 4xx as definitely failed. There is one POST and no retry (`actions.py:662-669, 733-744`; `connectors/jira.py:549-570`; `connectors/_http.py:174-189`).
- **Opaque links.** The HMAC is domain-separated and holds no document id in clear. Resolution uses `compare_digest` with no early exit. Token length is bounded, `doc.viewed` is written before the decision, and only `http(s)` redirects are allowed (`actions.py:319-321, 363-372`; `app.py:523-539, 641-644`).
- **Web proxy and the 303.** The proxy does not follow the redirect with the session cookie. It relays `Location` only on the open route and only for `http(s)` (`route.ts:219-228, 290-296, 316-321`).
- **Tickets never carry model text.** Tickets use a neutral default summary plus a fixed description of opaque links (`actions.py:552-554, 689, 734`).
- **Draft floor edge case.** A sentence of stopwords only is rejected (`actions.py:147-149`).
- **Deliverables identity.** Bodies forbid extra fields (`deliverables/routes.py:28-38`; `uploads.py:82-88`).
- **Uploads off means unmounted.** When the flags are off, the uploads router is not mounted (`uploads.py:362-370, 395-402`).
- **Upload refusals and caps.** The limiter runs before the body is read. Every refusal is the same 404. Body and decoded-file caps exist. A failed write-ahead append stops the Drive POST with a 503 (`uploads.py:263-264, 288-296, 318-356`).
- **Upload names are display-only.** Names are sanitized, and the mock stores files under generated ids (`uploads.py:138-150`; `apps/mock_platforms/mock_platforms/uploads.py:82-92`).
- **Export guard coverage.** CSV headers, cells, chart rows and citation metadata use `guard`. PPTX titles, table text, chart labels and notes use `ptext` (`deliverables/export.py:71-94, 180-251`). The ordering bypass is B1.
- **Export ownership and release.** Unknown, expired and foreign deliverable ids get one refusal. Export bytes follow the final ledger append. Request titles never enter the download filename (`deliverables/service.py:364-383, 419-424`; `deliverables/export.py:46-59`).
- **MCP untrusted-text frame.** Document text cannot reproduce the frame's open or close markers, because `<<<` and `>>>` are replaced before framing (`mcp_server.py:42-49`). Unknown and foreign receipt 404s share one message (`mcp_server.py:354-363`).
- **Compliance connector split.** The audit MCP tools need `compliance_officer` at the HTTP layer, whatever the tool arguments (`audit_mcp_server.py:79-115`; `audit/routes.py:90-92`; `app.py:124-128`).
- **Parser defences.** ZIP entry, expansion, ratio and path checks, DTD detection, PDF page limits and worker timeouts are present (`extract_files.py:153-225, 458-468, 548-570`).
- **Refresh reservation.** The engine refresh reservation is locked, and an audit failure releases it (`engine_refresh.py:129-153`; `sim.py:500-512`).
