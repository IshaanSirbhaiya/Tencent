## Findings

Counts: HIGH 3, MED 9, LOW 8 (20 total).

### HIGH

**H1. Closing "Add a document" drops focus to `<body>`** (`components/graph/GraphExplorer.tsx` ~L520-527, `components/sim/AddDocumentSheet.tsx` L121-130). The Add button opens the `Sheet` by `onClick={() => setAddOpen(true)}` and is not a `SheetTrigger`, so Radix has no element to return focus to. Measured: Esc after posting leaves `document.activeElement` = BODY in all four runs (en/zh, 1280/390). Keyboard and screen-reader users restart from the top of the page, and the presenter loses their place on stage. WCAG 2.4.3, 3.2.1. Fix: wrap the button in `<SheetTrigger asChild>`, or pass `onCloseAutoFocus={(e)=>{e.preventDefault(); addBtnRef.current?.focus();}}` as DeliverSheet does.

**H2. Engine refresh announces every second and drops focus** (`components/engine/EngineRefreshButton.tsx` L292-296, L288). The `<p role="status">` text changes every second ("Rebuilding the snapshot… 1 s · …", "2 s"…); measured six different strings in six seconds. A screen reader reads a new sentence every second for the whole minute-long build, which drowns every other announcement. Separately, clicking the button sets `disabled`, and focus falls to BODY (measured). WCAG 4.1.3, 2.4.3. Fix: make the live region carry only step changes ("Rebuilding the snapshot" / "Publishing" / "Reloading" / "done" / "failed") and put the seconds counter in an `aria-hidden` span; use `aria-disabled="true"` plus an early return instead of `disabled` (keep focus), and set `busy` for the visual spinner.

**H3. Add-note success leaves the form ready to double-post** (`components/sim/AddDocumentSheet.tsx` L55-60, L175; `useAddNote`). After "Posted to Slack · #db-migration" the textarea still holds the text and "Post to Slack" is enabled again (measured: value kept, `postDisabled=false`). One extra Enter or click on stage creates a duplicate Slack message in the demo world, two feed rows, and a second ledgered write. The upload tab has the same flaw (file and title kept, button re-enabled). Fix: on success `setText('')` (note) and reset file, title and the file input (upload), move focus back to the textarea or the file field, keep the status line.

### MED

**M1. Deliverable text is English in the zh UI with no `lang`** (`components/user/DeliverSheet.tsx` L481-483, L407, L522, L539-545, L562-566; i18n/deliver.ts header comment). Seen in zh at 1280: title "Table from your sources", label "Draft for your review", column headers, cells, scope note "Answers draw only on content you can access…" all English, next to Chinese chrome. Round 2 fixed this for ActSheet with `lang="en"`; Deliverables was not given the same treatment. WCAG 3.1.2, plain language. Fix: `lang="en"` on `deliver-title`, `deliver-label`, the table/chart/analysis content, `scope_note` and source titles when the UI is zh (or when the API returns an English-only field); better, have `/ib/deliverables` honour the UI language for `label`, `title` and `scope_note`, which are fixed strings.

**M2. One citation chip per table cell: 20 identical tab stops** (`DeliverSheet.tsx` L581-585, `Chips`). The mock pricing table has 20 cells, each followed by the same "[1]" button. Measured: 22 Tab presses from the tab list to the Copy button. Keyboard users must tab through 20 same-name buttons to reach Copy/CSV; screen-reader users hear "1" twenty times. It also makes the table visually noisy at 390 px (screenshots). WCAG 2.4.1, 2.4.3. Fix: show chips once per row (or once per table when every cell has the same tag) and fall back to per-cell chips only when a row mixes sources; or render the repeated chips with `tabIndex={-1}` and keep one per row tabbable.

**M3. Chip click opens a second modal on top of the Deliver sheet** (`DeliverSheet.tsx` L368-369 → AnswerCard `onCite`). Measured: after clicking a chip two dialogs are in the DOM (`deliver-sheet`, `sources-sheet`). On a phone the user loses the table they were checking, and Esc order and focus return across two stacked Radix modals were not verifiable in the time. WCAG 2.4.3, 3.2.2. Fix: close the Deliver sheet first (and reopen the same tab when the sources sheet closes), or render the source in the same panel as an inline expandable row (the "Cited in this table" list already holds the title).

**M4. Chart type word hard-coded in English** (`DeliverSheet.tsx` L648: `t('deliver.chartLabel', { type: 'Bar', … })`). In zh the chart's accessible name reads "Bar，FX margin by market，3 个柱，从 0.35% 到 0.4%", a zh voice spelling an English word. WCAG 3.1.1. Fix: make `deliver.chartLabelBar` its own key ("Bar chart, …" / "柱状图，…") like the line key.

**M5. Copy text is always English** (`DeliverSheet.tsx` L795, L799, L809-811: 'Sources', 'Series', 'Label', 'Value as written', 'Source'). A zh user who pastes into a note gets English column headings next to the Chinese UI they just saw. Fix: pull these from the same message keys (`deliver.col.*`, `deliver.sources.*`). The CSV from the server has English headers too (mock exportFile); document it or localise server-side.

**M6. "Regenerate" and "Try again" strand keyboard focus** (`DeliverSheet.tsx` L214-217, L516). Regenerate replaces the whole `Ready` view with the loading view, so the focused button unmounts; measured focus lands on `deliver-sheet` (the dialog container) after Enter. A keyboard user has to Tab from the top and the loading text is the only cue. WCAG 2.4.3. Fix: after retry, focus the `role=status` loading region (`tabIndex={-1}`), and after the new result arrives focus the title `h3` (tabIndex -1), or keep the old view mounted with `aria-busy` and a spinner on the button.

**M7. Live feed and Add button at 390 px crowd the graph** (`LiveFeed.tsx` L78; `GraphExplorer.tsx` ~L511-520, L594-606). Screenshots at 390: the "Add a document" button is squeezed so its label is clipped ("l a document" with the search icon overlapping), and the feed card (full width minus 2 rem, about 120 px tall once a note arrives) covers roughly a quarter of the canvas and the top of the Legend. The title "Knowledge graph" also wraps against the Explore/Compare toggle. At 1280 the feed overlaps the top of the Legend and the Legend's last row ("Links between documents") is cut off by the zoom controls. WCAG 1.4.10 is not violated (no scroll), but the demo's headline moment is hard to see on a phone. Fix: at `<sm` collapse the feed to one line (`compact` already exists: use it when `useIsMobile()`), icon-only Add button with `aria-label` below `sm`, and stack Legend below the feed with `max-h` and scroll.

**M8. Silent stale state when live updates stop** (`useLiveChanges.ts` L200-203; `LiveFeed.tsx` L73). On 401/403/404 the hook sets state `stopped` and stops polling, but `LiveFeed` shows no status for `stopped` (only `paused` and `unavailable`) and the Live-updates switch still reads ON. On stage this looks like "live, nothing new" when the feed is dead; for a signed-out session it hides a real problem. WCAG 3.3.1 (identify the error), 4.1.3. Fix: add `live.stopped` ("Live updates stopped. Reload to restart.", zh "实时更新已停止，请刷新页面。") and set the switch to off and disabled for that state; announce `unavailable` once through the polite announcer.

**M9. Engine status poll fails silently** (`EngineRefreshButton.tsx` L249-257). A single failed status poll runs `setSt(null)` and never reschedules, so a running rebuild vanishes from the screen: the button re-enables, the status line empties, and the person may start a second refresh (the server then answers 429 "One refresh every 2 minutes"). Fix: on a poll error keep the last state, retry with a short back-off, and show `eng.failed`-style text after 3 misses.

### LOW

**L1. Rule 4 wording hints** (i18n/graph.ts `add.channelHint` "Only channels you can already read are listed."; `add.desc` "a place you can already read"; `add.noChannels` "No Slack channel you can read is loaded"; i18n/deliver.ts `deliver.desc`/`deliver.hint`/`deliver.nothingHint` "sources you can still open"; `live.empty` "Changes you can open appear here"). Each sentence implies that other channels or sources exist that the person cannot open, and "still" implies that access may have been withdrawn. Rule 4 says never to hint. Content shown is not leaked, but the wording invites "which ones?". Fix: positive phrasing: "Your channels." / "Built from this answer and its cited sources." / "Nothing to build from this answer." (drop the nothingHint line, or make it "Try asking again."), "Nothing new yet." Keep the long privacy explanation in the Privacy notice only.

**L2. Drive folder is a raw id field** (`AddDocumentSheet.tsx` L211-213, default `fd-3`). A text input with `pattern` but no visible rule or error message; a presenter must remember "fd-3". Jargon for a normal user and a typo gives the neutral refusal with no clue. Fix: a `<select>` of the folders from the person's own map (same source as the channel list) with a plain label ("Drive folder"); if kept as text, add `hint` and an `aria-describedby` error.

**L3. Upload feedback is thin** (`AddDocumentSheet.tsx` L93-111, L201-208). File size is checked only on Upload, not on selection (a 20 MB pick reads the whole file first); the native file control shows browser-language text ("Choose file / No file chosen") even in zh; no selected-file name/size confirmation under the control; `soon` is sticky after one 405 and hides the form until the sheet remounts. Fix: check `file.size` in `onChange` with the same `add.tooBig` message; show "name · size" in a `role=status` line; clear `soon` on retry.

**L4. Success and error share `role="status"` and mount with their text** (`AddDocumentSheet.tsx` L113-118). Errors should be `role="alert"`; a live region that is created together with its content is announced unreliably by some screen readers. Fix: keep an empty `<div role="status" aria-live="polite">` mounted and swap its text; use `role="alert"` for `kind: 'error'`.

**L5. Feed "Show" buttons have no context** (`LiveFeed.tsx` L121-123). Up to five buttons all named "Show" ("查看"). Measured: `["Show"]`. WCAG 2.4.6, 2.5.3 (name must contain visible label, so add context after it). Fix: `aria-label={`${t('live.show')}: ${i.label}`}` (visible text still starts with "Show"). Same for the engine's "Show it" / "查看" link (which in zh reads as an unexplained "View"): label it "Reload the engine view".

**L6. Engine "Show it" is a bare button styled as a link, no focus ring class, and does `location.reload()`** (`EngineRefreshButton.tsx` L300). Reload drops the person's tab, entity and scroll position; ring depends on the global rule. Fix: add `focus-visible:ring-2`, and replace reload with the engine view's own refetch where one exists. Mid-sentence 12 px text target is about 14 px high (2.5.8 spirit; the `target-size` exception for inline links may apply).

**L7. Chart colour fallbacks** (`DeliverSheet.tsx` L649, L720-731). Only three colours; `colors[i]` is `undefined` for a 4th series (invisible bars) and the third (`--line-strong`) is a faint grey with low non-text contrast (1.4.11). Series are not distinguished by anything except colour when more than one (legend swatch only; no direct labels, line charts share dot shape). Fix: cap at three series (spec says server returns at most that? confirm) or cycle, use accent/fg/muted with distinct dash patterns, and keep the data table (already present).

**L8. Presenter D with no cache fails silently** (`components/presenter/deliver.ts` L139-147, controller.ts L325). `openDeliverables` returns `false` when the warm-up found nothing (kill switch off, no citations, signed out) and the key does nothing: on stage that is a dead key press with no message. Fix: when `false`, show a toast/HUD line "Deliverables not ready (press R to rebuild)" in the presenter bar's announce region. Also the answer behind the overlay (`DeliverOverlay.tsx` L14-18) is a plain fixed `div` with no landmark or heading: add `role="region" aria-label` so the page is not an unlabeled blank for a screen reader.
