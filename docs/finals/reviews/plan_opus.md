# Plan review: architecture and security (Opus)

Scope: `docs/finals/PLAN.md` and `DECISIONS.md`, `CLAUDE.md`, `docs/tencent/SECURITY.md`, and the backend
from commit `e5406b9`: `audit/stats.py`, `audit/routes.py` (`/audit/stats`, `/audit/journey`), `app.py`
(`/ib/trace`), `pipeline.py` (`stage_ms`) and `tests/test_dev_views.py`. I also read `audit/query.py`
(`reconstruct`, `_apply_locked`), `index.py` (`readable`, `search`), `knowledge_map.py`, the web proxy
`app/api/ib/[...path]/route.ts`, `scripts/run_walnut_original.sh`, `scripts/build_enterprise_graph.py` and
`apps/gateway/databridge_gateway/auth.py`. Paths are relative to `databridge/apps/internal_brain/databridge_ib/`
unless they say otherwise.

**What I ran.** I ran the IB suite once (read-only, with no caches, and a temporary folder in the
scratchpad): **645 passed in 68.8 s**. I did not run the e2e suite.

**Overall.** The three new endpoints keep the hard rules:
- `/audit/stats` and `/audit/journey` need `compliance_officer`, are ledgered (failures too), and read
  the verified ledger.
- `/ib/trace` takes identity only from the token, gives the same 404 for someone else's request and for
  an unknown one, and leaves out the considered set, Gate-2 verdicts and reason codes.
- `stage_ms` is measured over the asker's permitted corpus only (`index.search` scores only `allowed`
  chunks, and `readable` is cached per user), so I found no timing that depends on restricted content.

The real risks are in the **planned** work: the `/api/walnut` engine page, `/ib/graph`, `/ib/doc`, the
"View as" overlay and the seeded history. Two smaller leaks are in `/ib/trace` as built.

## Answers to the four questions

**1. Hard rules.** The built endpoints keep them. Identity comes from the token. Compliance views are
role-gated and write-ahead ledgered, and failures are ledgered. Trace gives the same 404 and no reasons
or considered set. Ledger failures are 503. Two leaks remain in trace: global `seq` (#4) and documents
that were released but never shown (#14). Trace is also not ledgered (#5). On the side channels:
- **Per-stage timings:** no restricted dependency found; update the docs (#13).
- **"+N more" badges:** safe only if every counted neighbour is Gate-2 confirmed in the same call, as in
  the map (#3).
- **View as:** safe only as a grey-only intersection, using an `openable` subset endpoint (#6).
- **Seeded history:** it must not put restricted topics into a persona's history, and it must be
  labelled (#7).
- **The engine page as planned:** this is the one real breach of the hard rules (#1).

**2. The `/api/walnut` proxy.** Not safe as described. It turns a loopback-only gateway into an
unauthenticated surface on all interfaces, with SSRF and model-call routes behind it. It also shows
jdoe's snapshot to every persona. Cut it. If it must stay, apply all of #2 and #1.

**3. Architecture and time.** One Next app, server-side aggregation and identity from the token are the
right choices. Cut and reorder as in #9: drop the engine proxy and the Trust page, trim the graph, run
the eval again now, freeze the contracts tonight, and seed before the analytics work.

**4. Test risk.** Backend: 645/645 pass today. The risk comes from B9 (window anchoring touches the
`test_audit_routes` window tests), B10 (`/health`, #15) and any edit to `pipeline.py` or `models.py`,
which the coordinator owns. Keep B5/B6 in new modules. E2E: high risk. The restructure breaks the
`goto` paths and the tour spec, and the suite only exercises mocks (#8). Add redirects, port each spec
within its owner's wave, and add a small live project for the rule-4 assertions.
