# Final security review (Opus), branch `final_v1.0`, 30 Oct

Scope: the finals additions: `databridge_ib/{graph,docview,authz}.py`; the `app.py` routes `/ib/graph`,
`/ib/graph/openable`, `/ib/doc`, `/ib/status`, `/ib/trace`, `/ib/ask/stream`; `audit/routes.py`
(`/audit/stats`, `/audit/journey`, `/audit/tamper-demo`); `audit/tamper.py`, `audit/nl_llm.py`, the
`nl_filter.py` title resolver; `sim.py` reconcile; the replay switch; the two web proxies
(`app/api/ib/[...path]/route.ts`, `app/api/walnut/[...path]/route.ts`); the pages under
`internal_brain_web/app`. Measured against `CLAUDE.md` (hard rules), `docs/tencent/SECURITY.md` §15,
`docs/finals/contracts/backend_v1.md` and the two plan reviews (`plan_opus.md`, `plan_codex.md`).
Python paths are relative to `databridge/apps/internal_brain/databridge_ib/`; web paths are relative
to `databridge/apps/internal_brain_web/`.

## What I ran

- **Backend suite** (read-only command as given): **733 passed**, 44 warnings, in 732 s. It ran alongside other agents' pytest and Playwright runs, which is why it was slow.
- **Live probes** against the running stack (web `next start` on 127.0.0.1:3100, IB on :8100), as
  `ken.ext` (contractor), `amy.am` and `maya.compliance`. Only demo-login, asks and GETs; no `/sim/*`.
  - `/ib/doc/confluence:cf-1001` (restricted for Ken) vs `/ib/doc/confluence:cf-999999` (unknown):
    same 404 status, body and headers (5 runs each; medians 141 ms vs 162 ms, noise).
  - `/ib/graph?focus=` the same two ids: same 404 status, body and headers.
  - `POST /ib/graph/openable` with each id: both `{"openable": []}`; only `as_of` differs.
  - Ken's P2 pair ("Q3 breach" vs "Q7 breach"): `/ib/graph?q=` gives identical graphs (0 nodes);
    `/ib/ask/stream` gives the same 7 stage events in the same order, and identical answers apart
    from ids and time; both `/ib/trace` receipts are identical apart from the rounded latency.
  - Host-header test: see finding 1.
  - Engine proxy: Ken 403; Maya 200 (see finding 2); a forged Host 403.
- `npm audit --omit=dev --package-lock-only` on the web app (finding 6).

## Verified safe

**Rule 4 (restricted is indistinguishable from non-existent)**
- `/ib/doc`: one `NotFound` path for unknown, outside Gate 1, live-denied, timed out and unconfirmable drift (`docview.py:44-49`). Live: identical status, body and headers for restricted and unknown. The output is whitelisted (`authz.public_meta`; no ACL, no raw links, no full text). Linked items resolve only inside `readable` and then pass Gate 2 live (`docview.py:60-71`).
- `/ib/graph`: candidates are bounded by Gate 1, then pass `authz.authorize` (live Gate 2 plus the pipeline's version-bound read-through). Nodes, containers, people and edges come only from confirmed documents. `degree_hidden_safe` / `count` are numbers only when the whole Gate-1 neighbourhood was checked, and they count only confirmed nodes (`graph.py:197-206, 273-284`). An unopenable focus and an unknown focus share one 404 (live: identical). Search scores the permitted corpus only (`index.py:303-316`, P2 statistics). Ken's P2 pair gives identical graphs.
- `/ib/graph/openable`: unknown and unopenable ids are both simply absent (live: identical apart from `as_of`). Capped at 300 ids, each ≤ 300 characters.
- Compare and "View as" (D-17): two independently signed-in graphs. `openable` posts only the LEFT side's own visible ids under the right person's session, so it cannot reveal anything the left cannot already see (`components/graph/CompareView.tsx:66-100`). No union, diff or placeholder. `PermissionBadge` is used only in `/dev/styleguide`, with static props.
- `/ib/ask/stream`: fixed stage names, all seven every time, the answer only after `released`, and the same JSON as `/ib/ask` (live: identical sequences for the P2 pair). An error is one fixed `error` event.
- `/ib/trace`: own requests only, through `projection.owns` before reconstructing anything (the same 404 for someone else's request and an unknown id). Stages are derived from record kinds, not timings. Latency is rounded to 100 ms. Records carry per-request ordinals and hashes, with no global `seq`. It lists only cited documents still openable now, re-authorised live, with no count of omitted ones. Plan_opus #4 and #14 and plan_codex #1 are fixed.
- `/ib/history`: the caller's own `request.accepted` rows, with `channel` and `synthetic_replay` (plan_opus #7b fixed). The seeder filters out restricted titles and keys per persona (`scripts/seed_demo_activity.py:8-19, 130-146`).
- `/ib/status`: authenticated; booleans, model ids and `ledger.ok` with a 15 s TTL; never a key or base URL. `/health` is still `{ok: true}`.
- User-mode and Mission-control screens show no org-wide numbers to a non-compliance user: stats and journey are 403 in the IB, the UI shows a lock card, and the eval figures are a static file.

**Identity from the token only**
- Every new route takes `Depends(current)` (cookie or bearer, verified and revocation-checked); no body or query field names a principal. The compare slot header only picks which signed cookie to forward (`route.ts:72-78, 199, 225`); slots reach only login/logout/whoami/ask/map/graph/openable. The client re-checks `sub` on every slot response (`CompareView.tsx:48, 52, 83`).
- Engine proxy: the browser's Cookie and Authorization headers are never forwarded. Identity comes from the IB's `/auth/whoami` with the `ib_session` cookie, on every request (no cache). `down` and `401` fail closed.

**Write-ahead ledgering and fail-closed**
- `doc.viewed` is appended before the access decision, so a ledger outage is the same 503 for every id. `graph.viewed` and `trace.viewed` are appended before the return; their not-found paths also append, so a ledger outage is a 503 on every path. `audit/*` stats, journey and tamper-demo ledger their failures (plan_opus #12 and plan_codex #5 for journey are fixed).

**Replay switch (`IB_REPLAY_KEY`)**
- It needs every one of: key length ≥ 24, not deployed, bearer token, loopback peer, a constant-time key match, and `X-IB-Replay-At` within 400 days and not in the future (`app.py:109-131`). The web proxy never forwards `Authorization` or any `X-IB-*` header (only the cookie: `route.ts:222-225`), so the switch cannot be reached through the browser. A deployed config refuses to start with a key (`config.py:58-59`). A replay failure keeps its label and event time (`pipeline.py:114-119`; plan_codex #7 fixed). The IB binds 127.0.0.1 by default.

**Engine proxy (`/api/walnut`)**
- Off unless `WALNUT_PROXY=1`, and refused when `IB_DEPLOYED=1`. GET only (other methods 405). A closed path allowlist, with each query parameter allowlisted and the query rebuilt. Segments are cleaned, and the outbound URL is re-checked against a fixed loopback upstream. Loopback Host and Sec-Fetch-Site checks (live: forged Host 403). The token comes from a server-only env var (no secret strings in `.next/static`). Upstream headers and Set-Cookie are never relayed. 5 MB cap, 10 s deadline, local file paths dropped. Ken is 403. The open issue is the compliance branch (finding 2).

**Tamper demo**
- Copies are taken under the ledger's append lock (`tamper.py:309-313`). Scenarios run on per-scenario copies, each verified with `IbConfig(var_root=<copy>)`, so no default path can point back at the live directory. Each scenario folder is removed after use; the whole temporary directory is removed in `finally`; one run per process (409 otherwise). `real_log_modified` re-hashes the live files' original bytes. Paths in the problem text are replaced with `<copy>`. The demo is compliance-only and ledgered write-ahead (started, then ok or the error).

**Hy3 audit parser**
- The rules run first. The model sees only the fixed prompt, the question and the clock (`audit/nl_llm.py:80-86`). Its reply must be a single JSON object with closed keys, then must validate as `AuditFilter` (`extra="forbid"`, patterns, 365-day cap); anything else falls back to the rules. An injected question can at most produce a filter the officer could already type; the model has no tools and no data. The title resolver works only on titles already in the compliance projection and never reaches the model.

**Web**
- The only `dangerouslySetInnerHTML` is `PREFS_INIT_SCRIPT` (`app/layout.tsx:28`), a constant string built only from constant key names; the values it reads from storage are compared against fixed literals. No other `innerHTML` or `eval`.
- `?mode` accepts only `dev` or `user`, and maps through `MODE_HOME` (`Providers.tsx:83-87`). The login redirect is a fixed path, with no `?next` parameter anywhere. All internal links are app paths with `encodeURIComponent` ids.
- CSRF on POST: Origin must match the site's own origin, and Sec-Fetch-Site must be same-origin or none; JSON only; 64 KiB cap. The cookie is `HttpOnly` and `SameSite=Lax`. `X-Frame-Options: DENY` and `nosniff` are set globally. (DNS rebinding is finding 1.)
- localStorage holds only theme, text size, language, mode, tour flags and per-request feedback; the compare cache is memory only.
- Presenter keys do nothing unless the presenter is armed (`?present=1`, Ctrl+Shift+P or an env flag). They are ignored in fields and with modifier keys. Reset only signs the demo sessions out and never calls `/sim`.
