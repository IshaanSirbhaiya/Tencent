## Verified OK

**Web proxy (`app/api/ib/[...path]/route.ts`)**
- The new `ib/open/<32 hex>` route is on the main-session allowlist only. It is not in `SLOT_ALLOWED`, and neither are Act and Deliverables, so a compare slot cannot reach them.
- The GET cross-site exception applies only to that exact path and only for a navigation. Every other GET still needs `same-origin`/`none`/absent `Sec-Fetch-Site`. POSTs still need a matching Origin and Sec-Fetch-Site. The DNS-rebinding Host check runs before routing and before any body is read.
- The 303 is relayed only on the open route, only for an absolute `http(s)` Location, and with no Set-Cookie. The global `Referrer-Policy: same-origin` (`next.config.mjs`) means the token is not sent as a Referer to the source system. `X-Frame-Options: DENY` and `nosniff` cover every route.
- Body caps: 64 KiB, and 7 MiB only for `sim/upload-file`. Both a content-length pre-check and a streamed count apply, and the read is under one 90 s deadline. On Lighthouse, Caddy caps bodies at 64 KB, so the 7 MiB exception exists only on the local stack.
- Content-disposition is relayed only for `ib/deliverables/export`, only on 200, and only in the exact shape `attachment; filename="walnut-<kind>-<hex8>-<yyyymmdd>.(pptx|csv)"`, plus `nosniff`. Upstream 5xx bodies are replaced (only the two known 503 texts are kept).
- The segment cleaning and the post-parse outbound re-check are unchanged and still applied.

**Other web code**
- `app/api/walnut` (engine proxy): unchanged in this range. It is off unless `WALNUT_PROXY=1`, off under `IB_DEPLOYED`, GET only, needs a loopback Host, accepts only the persona the snapshot was built for (checked through the IB's whoami), uses a fixed upstream, and never relays browser credentials. There is **no `middleware.ts`** in the web app, so there was nothing to review there.
- Model labels (honesty): `MOCK_MODEL_LABELS` is true only for `NEXT_PUBLIC_IB_MOCK_MODEL=hy3`. HY3 and DEEPSEEK both fall back to `deterministic/extractive-v1`. The mock `ib/status` reports an inactive chain and `key_configured: false`. The mock Analysis is `needs_model` with `fallback: no_model`. The offline launcher builds with `=extractive` (`demo_day.ps1:526`). No other hard-coded `hy3` label is left in `lib/mock`, `components/presenter` or `app/present`. The preflight board says "never claim Hy3" when the model is not live. `record_finals.cjs` takes the Hy3 caption from `/ib/status` and refuses a take when `FINALS_HY3` disagrees with it.
- Sign-out and persona switch from the shell drop `ib.presenter.deliver` and fire `ib:signed-out`. `clearDeliverCache` closes the overlay and clears the pending restore. R logs out through the session chain before it clears the cache (no race there).
- The grow steps are opt-in per tab (`?grow=1`, sessionStorage only). Esc with a dialog open never hides the HUD.

**Demo kit**
- `hy3_check.py`: `{}`, an HTTP-200 error envelope, a missing `choices` and empty content all count as **not** live (`completion_text`). The key is never printed, and `demo_up.sh` uses only the exit code (only the first model counts).
- `demo_up.sh` wipe guard: refuses `..`, absolute paths and backslashes; requires `var/?*`; and requires the resolved path to be **strictly** inside the resolved `var/`. So `var/.`, `var//` and a symlink pointing out of `var/` are refused. A missing directory is a no-op.
- Port-scoped kill (`owned()` in bash, `Test-OursCommandLine` in PowerShell) needs the repo path in the listener's command line. Checked against the real processes on this machine: the venv's Python **child** keeps `E:\...\databridge\.venv\Scripts\python.exe` in its command line, and the Next child is `node "E:\...\internal_brain_web\node_modules\...\next" start`, so our listeners match and a foreign process on a demo port is reported and left running. `taskkill /T` takes the multiprocessing workers with the parent.
- `demo_preflight.py` and `check_absent.py` send the demo sign-in to loopback only by default; a remote target needs `--allow-remote` **and** https, and a URL with credentials is refused. `check_absent` now passes only when `documents_containing` is exactly the integer 0.
- `fill_template.py`: `--name` cannot leave `templates/out/` (plain name, resolved parent check), and an existing file is not overwritten without `--force`.
- The root `.cmd` launchers are unchanged in this range; they pass only fixed flag rewrites to `demo_day.ps1`.
