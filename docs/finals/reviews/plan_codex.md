# Build-plan technical review

Reviewed 2026-10-30, branch `final_v1.0`. Paths below are relative to the repository. Static review plus isolated, in-memory Python checks; no service was started and no source file was edited. Severity ranks reflect the stated restricted == non-existent requirement. Future implementation risks are explicitly labelled hypotheses.

## Ranked findings

1. **high — `databridge/apps/internal_brain/databridge_ib/app.py:200` — Own trace returns documents beyond the answer disclosure, without current authorization.** `audit/query.py:499` enriches every retrieval-released document with title/container, and `app.py:200` returns these verbatim. These are model-context documents, not necessarily citations: `pipeline.py:148` builds them before composition, whereas `pipeline.py:182` clears citations on refusal and otherwise selects only cited passages. Thus even a refusal or a failure after retrieval can expose retrieved IDs/titles/counts through trace. A later revocation also leaves these titles and historical citation IDs accessible: trace checks request ownership, not document access. This contradicts “only what they were already shown” in `docs/finals/DECISIONS.md:13`; it does not mean Gate-2-denied documents directly enter `released`.
   **Fix:** Define an explicit asker-safe trace DTO from the actual public answer receipt; remove retrieval `released`. Under the requested current-permission rule, live-authorize historical document references before returning them and omit denied/missing entries identically, including their counts. Keep full historical retrieval details in the compliance journey. Add refusal, post-retrieval failure, uncited-document, and revocation regression cases.

2. **high — `docs/finals/PLAN.md:70` — The planned locked-node comparison contradicts the non-existence invariant.** The graph explicitly greys and locks nodes another persona cannot open; the demo repeats this at `PLAN.md:172`. Such a graph shows that hidden objects exist, their number, and potentially their topology. `DECISIONS.md:12` instead promises everyone their own graph. **Hypothesis:** Combining two valid session results into a shared comparison graph will leak one session's permitted data into the other persona's view unless the product defines a distinct authorized observer context.
   **Fix:** Render independent, filtered per-session graphs without hidden placeholders or missing-node counts. If a privileged comparison is required, make it a separately authorized compliance feature and never describe its union graph as the restricted persona's view. Resolve this contradiction before frontend implementation.

3. **high — `databridge/apps/internal_brain/databridge_ib/app.py:198` — Fine-grained trace timings provide a denial-side-channel.** `pipeline.py:133` skips source checks when there are no candidates; stale Gate-1 permission followed by live denial executes Gate 2 instead. `pipeline.py:187` records this difference and trace exposes it with millisecond precision. **Hypothesis requiring paired runtime measurement:** A source-revoked document still in the index can be distinguished from an absent document even though neither is cited. Hashes are not plaintext disclosure, but global ledger sequence numbers returned at `app.py:202` additionally let an employee measure intervening organization-wide ledger activity, contrary to the organization-number restriction in `DECISIONS.md:12`.
   **Fix:** Keep raw stage timings and global sequence numbers compliance-only. Provide coarse, public-safe stages and an opaque per-request receipt to ordinary users. Test denied-versus-absent timing distributions with stale ACLs, timeout/429 outcomes, cold/warm caches, and concurrent load; changing body shape alone does not establish timing equivalence.

4. **high — `databridge/apps/internal_brain/databridge_ib/knowledge_map.py:43` — “Like the map” is not sufficient version-safe authorization for B5/B6.** The map accepts `checks[d].allowed` and then emits indexed title/version/link at lines 47–55. `models.py:148` includes `drift_material` in allowed verdicts. The Confluence checker explicitly reports changed versions (`connectors/confluence.py:397`). Unlike `pipeline.py:222`–235, the map never fetches the new version, rechecks its ACL, or verifies that fetched and checked versions match. Current access to a document does not establish access to obsolete content removed from its current version. **Hypothesis:** Copying this into B6 can expose a stale passage; B5 can expose removed titles/links.
   **Fix:** Share a version-bound read-through helper based on the pipeline's existing logic: fetch on drift, obtain fresh ACL, apply `acl.allows`, mask content, require the checked version, and deny on any uncertainty. Serialize an immutable authorized snapshot rather than re-reading a mutable index row after checks. Apply this to metadata and every graph endpoint as well as passage text.

5. **medium — `databridge/apps/internal_brain/databridge_ib/audit/routes.py:244` — Stats aggregation and some journey failures bypass the audit ledger.** Stats computation occurs outside a failure handler; exceptions return an unledgered 500. Journey catches reconstruction errors at line 259 but calls `_sync()` before that try at line 256; `_sync` only catches `LedgerUnavailable` (line 111), so projection/SQLite exceptions bypass `_refuse`. The existing contract at lines 12–18 promises ledgered handler failures. `ledger.py:116`–123 can yield an unparsed event, and `ledger.py:295` still supplies its raw data; strict chain verification is not event-schema validation. An in-memory malformed aggregation payload raised `ValueError` at `stats.py:105`; this demonstrates the missing handler, not that normal validated writes emit that payload. Trace also has no read audit event, on success or failure (`app.py:186`–203).
   **Fix:** Catch computation/projection failures while the ledger is writable, append a sanitized error event, and return a fixed error envelope. Distinguish true ledger failure (cannot promise to append; fail closed with 503) from query failure. Explicitly document and implement the trace-read audit policy. Authentication/role dependency rejection is an existing documented pre-handler exception, not an audit-route bypass.

6. **medium — `databridge/apps/internal_brain/databridge_ib/audit/routes.py:241` — Every dashboard refresh verifies and materializes the complete ledger.** `ledger.py:285`–296 verifies the whole chain before `after_seq` filtering; stats then scans all events and sorts latency samples (`stats.py:34`). The days parameter does not bound input work. Each successful read appends another audit event. Journey and trace also call `projection.sync`, which loads/sorts all ledger events and compares full sequence/hash maps (`audit/query.py:217`–225). **Hypothesis:** Frequent refreshes, seeded history, and concurrent trace reads will contend with live answers; no load benchmark was run.
   **Fix:** For the three-day build, avoid rapid polling, coalesce concurrent refreshes, and measure at realistic ledger sizes. For durable scale, aggregate incrementally against a verified snapshot/head with authenticated append notifications and rollback/rewrite invalidation. A cached aggregate must not be served when integrity cannot be established. Merely adding `after_seq` does not avoid full verification in the current implementation; keep strict verification until a safe replacement exists.

7. **medium — `databridge/apps/internal_brain/databridge_ib/pipeline.py:92` — Replay failures lose their replay label and event time.** Accepted/retrieval/release records share `event_time` and `synthetic_replay` at line 104, but `RequestFailed` uses the wall clock and the model's default `synthetic_replay=False` (`models.py:207`). Stats excludes replay per event (`stats.py:69`), so failed seeded requests become live failures with no corresponding live requests. An in-memory check reproduces `requests=0, failed=1` under replay exclusion.
   **Fix:** Propagate the original replay flag and effective event time to the failure event; consider request-cohort aggregation when filtering related lifecycle records. Add a failing replay test and a failure-before-acceptance case. Pipeline already attempts a sanitized failure append and re-raises; failure to append when the ledger itself is down is correctly best effort, not silently successful work.

8. **medium — `databridge/apps/internal_brain/databridge_ib/audit/stats.py:67` — Window has no upper bound.** Only events older than `since` are excluded, yet the response claims `until=now` (line 130). A direct in-memory check with `now=2026-10-30` counted a 2026-11-01 request. Backdated/future replay and clock skew make this visible in the planned analytics.
   **Fix:** Apply a documented interval, preferably `since <= event_time < now`, normalize timezone handling, and test both boundaries. Choose an explicit demo-world anchor for B9 rather than silently relabelling a wall-clock window.

9. **medium — `databridge/apps/internal_brain_web/app/api/ib/[...path]/route.ts:49` — B5/B6 and comparison slots need explicit proxy contracts.** The new stats/journey/trace allowlist entries exist at lines 34–36, but graph/doc are absent from the main allowlist; slots B/C permit only login/logout, whoami, ask, and map. **Hypothesis:** The planned graph comparison/source sheet will return proxy 404s if only backend routes are added or if main-session permissions are reused for slot data.
   **Fix:** Add exact GET patterns for graph and doc once their identifier contract is settled, and deliberately add only needed per-persona reads to the slot allowlist. Keep audit/sim excluded from slots; use each slot's signed cookie, never a caller-supplied subject. This is an integration gap for planned work, not a currently exploitable traversal defect.

10. **low — `databridge/apps/internal_brain/databridge_ib/pipeline.py:185` — Stage waterfall omits durable release work.** Stage timings stop before `answers.put` and the `answer.released` append. The `seal` stage measures only `retrieval.decided`; `latency_ms` includes content storage but is computed before the final ledger append at lines 189–197. A dashboard labelled end-to-end latency will understate response time, especially with slow durable writes.
    **Fix:** Label existing metrics as pre-release timings and retrieval sealing, or add a separate completion measurement with a clear audit design. Do not claim these stages cover final release. Test with deliberately slow store/ledger doubles; current test coverage only checks keys and nonnegative integers (`tests/test_dev_views.py:42`).

## Role checks and proxy boundary conclusions

- `/audit/stats` and `/audit/journey` both use the dependency created with `COMPLIANCE_ROLE` (`audit/routes.py:46`, `:84`, `:225`, `:250`). Actual authorization checks the current directory user's roles (`app.py:66`, `:73`–77), not a requested subject or the UI mode. An `admin_it` without `compliance_officer` is excluded. Journey intentionally exposes considered IDs/titles/containers and Gate-2 verdicts to this role (`audit/query.py:497`–509), with no stored answer text; successful results and missing targets are ledgered.
- `/ib/trace` accepts employee/compliance/admin roles but requires the request owner (`app.py:182`, `:192`). Other-owner and missing requests use the same 404 body. It does not directly return `considered` or `gate2`; findings 1 and 3 describe the remaining disclosure issues. Reconstructing another user's full request before ownership checking also costs more than a missing lookup (`audit/query.py:466`–472); use an ownership-constrained lookup and assess timing rather than treating equal status alone as proof.
- No traversal or unintended-prefix bypass was found in the added proxy entries: their regexes are anchored, request IDs have a restricted alphabet, dot/slash/backslash segments are rejected (`route.ts:63`), segments are encoded and the parsed outbound URL is rechecked (`:210`–215), and redirects are manual (`:230`). Query parameters cannot replace the constructed path. The existing broad `/sim/[a-z][a-z-]*` pattern (`:39`) is not introduced by these endpoint additions; enumerate actions if the intended policy is a closed route list. Existing traversal tests cover accessor paths (`tests/e2e/proxy.spec.ts:21`), not the new route variants; add suffix, encoded separator, double encoding, method and slot-isolation cases.

## B5/B6 design recommendations

1. **One principal and one authorization helper.** Reuse `principal_dependency`/`EMPLOYEE_ROLES`, `index.readable(user, directory.epoch)` (`index.py:289`), and `acl.allows` (`acl.py:36`). No `view_as` identity parameter. An ID outside the readable set and an absent ID must enter the same negative-result path before metadata is serialized. Never use unfiltered `doc_ids()` or `docs_in_container()` as the output universe (`index.py:280`–284).
2. **Live checks plus version-bound snapshots.** Call `gates.check_all` with known versions; all forbidden/vanished/unverifiable/timeout outcomes are negative. Reuse the pipeline read-through semantics described in finding 4, not merely the map's `.allowed` filter. Retain an immutable checked version/ACL snapshot, and reject or restart if the index/directory authorization version changes during construction. Do not expose raw ACL expressions or group lists as “Why I can see it”; return only an authorization explanation safe for this principal.
3. **Construct a visible induced graph.** Search only permitted documents using `index.search(query, allowed)` (`index.py:301`), then live-authorize candidates before emitting nodes, counts, edges or ranking-derived summaries. Resolve links within the permitted set as `_resolve_link` does (`pipeline.py:284`). Every edge needs two authorized endpoints and authorized supporting evidence. Derive containers/authors solely from visible documents; no empty private containers, dangling restricted IDs, global degrees, or hidden-neighbour badges. Live-denied documents must not consume public result caps or alter visible pagination. If exact permitted-neighbour totals require unbounded live checks, omit `+N` rather than estimate from Gate 1. Use a small fixed hop limit and an independent bounded worker pool; the map's 45-second batch (`knowledge_map.py:28`) is unsuitable for repeated interactive expansion without latency measurement.
4. **Same negative envelope and timing class.** For B6 and an explicit unavailable B5 focus, choose one constant 404 body, identical headers and no echoed identifier/title/count. For an ordinary empty search choose a fixed empty graph shape with visible-only counts. Missing and Gate-1-denied targets should execute the same local lookup path. A stale Gate-1 target can incur a live check whereas an absent target does not: normalize *all* negative exits to a common bounded response schedule, including timeout and drift-fetch failure, with bounded work/concurrency. Padding only one denial type or adding random jitter is insufficient. Confirm the resulting distributions under load; the current helpers do not themselves prove timing equivalence.
5. **Document output is a whitelist.** Return the checked version, masked passage and narrowly selected connector/index/authz timestamps. Do not return the index row wholesale: it contains raw ACL, full text, author and links (`index.py:228`–234). Filter or omit linked-object identifiers in structured lineage. Do not invent versions/history: the index stores one current row per document (`index.py:174`, `:227`), not a version history or general entity/mentions graph. Recheck access when opening the sheet even if a graph node was authorized earlier.
6. **Audit and test the public boundary.** Ledger authorized graph/doc reads before releasing content and record sanitized handler failures when possible. Keep denial reasons in the compliance audit only. Use paired worlds with/without restricted documents and compare status, JSON, headers, counts, topology, pagination and timing class. Include lost webhooks, drift, timeout/429, source deletion, concurrent updates, cross-slot sessions and ledger failure. Compare whole public payloads rather than checking only that a `gate2` key is absent (the current trace test at `tests/test_dev_views.py:101` does the latter).

## Three-day schedule risks

- **Highest: graph authorization and comparison semantics.** B5/B6 are still todo (`PLAN.md:127`–128) while the graph UI depends on their contract (`:153`). People/mentions/versions exceed the current index schema (`index.py:174`–179). **Hypothesis:** Shipping graph layout, rich panels and security-correct comparison together will consume the available window. Freeze a one-hop documents/containers graph and current-version sheet first; defer locked comparison and historical versions.
- **Highest: foundational UI dependencies and late integration.** `PLAN.md:150`–159 places most UI work behind Wave 0 and integration tests behind Wave 1, yet the target package currently includes only Radix Dialog among the proposed component libraries (`internal_brain_web/package.json:15`–21). **Hypothesis:** shared shell/API/types, new chart/graph libraries, bilingual text and two-theme accessibility will bottleneck integration. Freeze response types and one complete Ask → source → trace flow early; integrate tests daily and defer secondary surfaces before the final review window.
- **High: live Tencent dependency.** The plan itself records TokenHub 402/401006 (`PLAN.md:90`), while the demo requires a named Hy3 answer and WorkBuddy (`:174`). **Hypothesis:** activation or connectivity can remain unavailable independently of code completion. Require one end-to-end live success early, record it immediately, and keep the declared extractive fallback honest; do not make rehearsal readiness depend on activation.
- **Medium: mock/live mismatch and evidence regeneration.** The proxy routes mock-mode requests through `handleMock` (`route.ts:196`–205); mock audit routing ends in 404 (`lib/mock/server.ts:265`) and the general handler ends in 404 (`:295`), with no stats/journey/trace handlers. **Hypothesis:** new pages tested only against mock mode will fail or require unplanned mock work. Add explicit mock contracts or run these pages against the real backend. B8 requires a fresh evaluation (`PLAN.md:130`); schedule it before freeze and label results by actual revision/configuration rather than carrying forward the quoted numbers.
