# Read-only review of the deliverables build plan

Reviewed branch `final_v1.1` (`.git/HEAD`) on 30 October 2026. Paths below are relative to the repository root; `PLAN` means `docs/finals/deliverables/PLAN.md`. This reviews proposed behavior, not an implemented deliverables endpoint. No critical exploit in an existing deliverables endpoint is asserted. Hypotheses identify implementation-dependent risks.

Evidence: source inspection plus read-only Python probes (`-B`, no bytecode writes). Numeric probes executed the repository's `value_forms.py`; PowerPoint probes used the repository-local `databridge/.venv` and held all files in memory. No network, GUI, installs, or test suites that write fixtures were used.

1. **High — Current-source evidence can be manufactured from an old answer.**
   **File/section:** PLAN §§4.1, 5; `databridge/apps/internal_brain/databridge_ib/actions.py`, `ActionService.context` (263–301); `authz.py`, `AuthorizedDoc` and `_snapshot`; `pipeline.py`, `AnswerReleased` construction (227–232).
   **Finding:** `context()` verifies the sealed answer and reauthorizes documents, but obtains `facts` from that old answer without checking them against the new snapshot text. PLAN defines `P[tag]` as old cited sentences plus current excerpts, then treats everything in P as evidence for the current version. If v4 said 0.35% and v5 removed it, the old sentence can make 0.35% pass while the citation and banner say this uses v5. A multi-tag answer sentence copied into each tag's passage also lets a value originally supported by C2 pass as C1 evidence. The immutable snapshot itself is useful; mixing provenance above it is the flaw.
   **Fix:** Keep answer sentences as task context, separate from admissible evidence. Verify output only against the corresponding snapshot's source text, with retained source spans/rows and version. Do not copy multi-source synthesized sentences into each individual source's evidence. Explicitly map sealed tags to original versions, including `context()`'s legacy untagged-record behavior.

2. **High — Reusing `Passage.line()` destroys the boundaries the verifier and offline table need.**
   **File/section:** PLAN §§4.1, 4.4, 5.1; `databridge/apps/internal_brain/databridge_ib/narrate.py`, `Passage.line` (88–92), `build_context` (95–96); `databridge/fixtures/enterprise/world.json:4812`.
   **Finding:** `Passage.line()` calls `" ".join(text.split())`, collapsing all document rows into one line. PLAN says P is the passage as sent to the model, yet requires same-line matching and CSV blocks with multiple lines. The actual demo source contains separate SG, HK and ID rows; after this serializer they are one line. Under a line-based implementation, ID can inherit SG's 0.35%; CSV detection on serialized P cannot work. Keeping original P separately would avoid flattening, but must be specified and must match exactly the excerpt actually sent.
   **Fix:** Introduce a deliverables-specific evidence representation with preserved row/sentence boundaries and offsets. Serialize those boundaries explicitly; run CSV extraction and co-location on those same retained units, excluding citation headers and metadata. Apply global excerpt truncation before establishing the evidence map.

3. **High — Substring matching and the number tokenizer do not prove the claimed numeric identity.**
   **File/section:** PLAN §5.1 steps 2–3 and §5.5; `databridge/packages/core/databridge_core/value_forms.py`, `_NUMBER`, `value_spans`, `number_key`.
   **Finding:** `norm(raw) in norm(P)` accepts `35%` inside `0.35%`, or `20` inside `20000`; parsing raw alone then validates the wrong value. The actual tokenizer returns one numeric span with key `20` for `20k`, so `raw="20k", value=20` passes that part of the specification despite the blanket promise that abbreviated numbers never verify. Probes also found `(500)` becomes positive 500, `SGD20000` is a token rather than a number, `SGD20,000` is numeric, and lowercasing the latter before tokenizing loses that recognition. European decimal/grouping forms and space-grouped thousands do not normalize like comma-grouped English numbers. `number_key` accepts a string and calls `.replace`; passing the described Decimal object directly raises `AttributeError`.
   **Fix:** Match complete source numeric spans with boundaries, then compare parsed source and proposed values. Define an explicit supported literal grammar, rejecting scale suffixes, unsupported locale/accounting forms and ambiguous signs. Preserve case for the existing parser; apply Unicode normalization consistently without losing offsets. Pass `number_key(str(value))` or an explicitly formatted finite Decimal string. Reject booleans, NaN, infinities and impractically large magnitudes at schema validation.

4. **High — Label co-location is not label-to-value or unit binding.**
   **File/section:** PLAN §§3.3, 5.1 steps 4–6, 5.2 and 5.3; `value_forms.py`, `ValueSpan`/`value_spans`; `databridge/apps/gateway/databridge_gateway/llm.py`, `_fact_matches` (1093).
   **Finding:** Even with preserved lines, `SG 0.35%, ID 0.4%` satisfies same-sentence membership for the wrong ID/0.35 pairing. The check binds only `x`, not the series metric: a line containing several metrics supports swapping them. A currency code anywhere on a multi-currency line is equally insufficient. Only percent and currency have substantive unit rules; `20 hours` can be presented as days or count. Text numbers are compared by numeric key, so percent/currency semantics can also change in prose. Unit consistency is specified per series, although the chart has a single global unit and currency.
   **Fix:** Bind each value to its row/entity, metric column and unit using explicit source spans and headers. Initially support one metric, one unit and one currency per chart, rejecting ambiguous prose and mixed currencies. Validate all series against the chart unit, including count/days/hours/points. For tables, preserve source row and column associations; token membership alone cannot prove a comparison cell belongs in its proposed row.

5. **High — Version/permission changes during generation and export lack a defined policy.**
   **File/section:** PLAN §4 steps 2–10, §6; `databridge/apps/internal_brain/databridge_ib/authz.py`, `authorize` and `_snapshot`; `actions.py`, `Context`.
   **Finding:** A snapshot is bound at authorization time, not locked through a 30-second model call. Generation has no post-model check. Export reauthorizes document IDs but removes only inaccessible documents; an accessible document whose text/version changed leaves an old verified spec intact. **Hypothesis:** callers can receive newly generated content after revocation, or exports whose current metadata falsely implies fresh evidence verification. Partial removal also needs to cover titles, column labels, series names and speaker notes derived from revoked tags, not merely tagged body items. A multi-tag item must require ALL dependencies, as `context()` already does for facts.
   **Fix:** Store evidence versions/digests and dependency tags for every derived field. Before release/export, reauthorize and compare versions; on drift, fail closed with a regenerate response or reverify against the new source. Recursively prune and revalidate all content and metadata, including minimum point counts. Record actual authorization timestamps and state the remaining point-in-time limitation rather than promising continuously current access.

6. **High — Native PPTX charts introduce an embedded-workbook formula path.**
   **File/section:** PLAN §§5.2, 6.1–6.2; `databridge/.venv/Lib/site-packages/pptx/chart/xlsx.py`, `_write_cat_column` and `_write_series` (154–176).
   **Finding:** The CSV guard does not cover PPTX. The installed chart writer calls `worksheet.write` on category labels and series names. An in-memory probe with category `=1+1` and series `=2+2` produced `<f>1+1</f>` and `<f>2+2</f>` in the embedded XLSX. Source-grounded strings can still be spreadsheet syntax. **Hypothesis:** a label that passes the proposed word/value checker can reach this path; equality with source text is no formula defense. No external formula was executed in the probe.
   **Fix:** Treat chart category/series strings as untrusted spreadsheet input. Reject formula-bearing labels before chart construction or ensure the embedded workbook writes them as literal strings without changing displayed semantics. Test the embedded XLSX XML for formula nodes and external links, not just PPTX slide text.

7. **High — Export authorization must precede existence-dependent validation.**
   **File/section:** PLAN §§3.1, 3.4, 4 and 6; `databridge/apps/internal_brain/databridge_ib/app.py`, `principal_dependency` (101), `_employee` (167), Act routes (474–500); `actions.py`, `ActionService.context` ownership-before-reconstruction.
   **Finding:** Generation's ownership reuse is sound. Export cannot get ownership protection merely by calling `authz.authorize`: that checks source access, not ownership of the stored deliverable. PLAN requires owner storage and a uniform 404, but does not explicitly order ownership/expiry checks before checking kind/format compatibility. **Hypothesis:** checking a foreign stored kind first yields a distinguishing 422, or source access alone permits someone else's artifact. This is a new-endpoint implementation risk, not an observed existing bypass.
   **Fix:** Both routes must use `Depends(current)` and `_employee`, then the feature flag. For export, validate syntactic format, retrieve under the store lock, check owner and TTL with one 404, and only then validate kind-format compatibility and reauthorize sources. Never accept identity/spec/content from the client; keep export outside `SLOT_ALLOWED`.

8. **Medium — Store publication precedes the required creation seal.**
   **File/section:** PLAN §4 steps 8–9, §7, T7–T8; `databridge/apps/internal_brain/databridge_ib/actions.py`, `_append`, `_lock` and proposal storage.
   **Finding:** PLAN inserts a verified spec before `deliverable.created` succeeds. A failed ledger append leaves an unsealed entry unless explicitly rolled back. There is also no specified atomic TTL/eviction/publication behavior, and export pruning can accidentally mutate a shared stored spec. T8 says hash canonical response content while §7 says canonical JSON of what is returned; those need one precise definition.
   **Fix:** Build an immutable response privately, compute its canonical digest once, append `created`, then publish an exportable entry under a lock. Export from a copy; do not alter the sealed original. Specify JSON canonicalization and which fields are hashed. Test creation-write failure, concurrent export/regenerate, TTL and eviction.

9. **Medium — Structured-call integration is feasible, but the timeout is not a cancellation budget.**
   **File/section:** PLAN §4.2 and §11 risk 3; `databridge/apps/internal_brain/databridge_ib/llm.py`, `_config_for` and `ModelChain`; `databridge/packages/harness/databridge_harness/client.py`, `complete_structured` (160–246), `complete_text` (248); `backends.py`, `LiteLLMBackend.generate` (136).
   **Finding:** The proposed call signature fits the harness: pass task, messages, response model, `seed=7`, `max_retries=1`, then consume `StructuredResult.parsed` (not the result wrapper). Adding `ib_deliver` routing is necessary. The harness exposes no timeout parameter and its backend call here supplies no timeout. A pool timeout only stops waiting; the model call/retry can continue consuming resources. **Hypothesis:** repeated timeouts exhaust the small pool or its queue, while queued work starts after the request has already fallen back. Authorization alone can additionally take 20 seconds.
   **Fix:** Specify a deadline covering queue wait and all model attempts, bounded admission, transport timeouts and no retry/fallback after expiry. Late workers must never publish or append success events. Clarify whether the 30 seconds is model-only or total route latency. In JSON-off mode use whole-object parsing with an optional enclosing fence: the cited `audit/nl_llm.py::parse_filter_json` does NOT extract the first brace block, and a naive brace match breaks nested deliverable JSON.

10. **Medium — Output schemas and UI states are not internally complete.**
    **File/section:** PLAN §§2.4, 3.2–3.5, 5.1–5.2; `databridge/apps/internal_brain/databridge_ib/models.py`, `Citation`, `ModelInfo`, `AskResponse`; `databridge/apps/internal_brain_web/components/user/SourcesSheet.tsx`, `SourcesSheetProps` (17–25).
    **Finding:** There is no wire state for “too little to chart”: only ready/needs_model exist, while filtering can leave zero series. Dropping columns/sections can violate required minima, and row lengths have no explicit equality constraint with column count. `needs_model` forces zero counts even when rejected model output caused it. Numeric table cells lack `{raw,value,x,tag}` required by §5.1. Timeline dates and labels need no shared occurrence. Deliverable citations match Act's metadata, but do not satisfy the existing full `Citation` type (missing content/authz timestamps), and `SourcesSheet` accepts an `AskResponse`, not a deliverable.
    **Fix:** Define discriminated request/model/verified-response schemas and cross-field validators before coding the verifier. Specify insufficient-data status/reason, empty-result rules and count meanings. Give table cells an explicit row/column evidence binding. Adapt the source sheet using the original answer's citation index, or explicitly broaden its input with the necessary checked timestamps; do not cast incompatible objects. Bind timeline labels to date occurrences too.

11. **Medium — Text checks do not implement the stated rejection of invented names.**
    **File/section:** PLAN §5.2, T6; `databridge/apps/gateway/databridge_gateway/llm.py`, `unsupported_named_terms` (1260), `_AT_SENTENCE_START`, `_NAMED`; `databridge/apps/internal_brain/databridge_ib/grounding.py` re-exports.
    **Finding:** The actual helper exempts sentence-initial capitalized terms and searches later terms as substrings. A sentence such as “Zorblax charges 0.35%.” can pass if charges and 0.35 exist in the cited text. Lowercase and non-Latin invented entities are outside the ASCII-capitalization heuristic. T6's two-word example does not cover this. These are existing wall limits, but the new plan claims broader coverage and exports the result with provenance language.
    **Fix:** For this time budget, favor extractive source text and entity/label token matching at boundaries. Test initial, lowercase, substring and Chinese names. Describe heuristic limits accurately; do not claim all invented names or semantic relationships are verified.

12. **Medium — PPTX APIs and file-size approach are sound; chart mapping and rendering need specification.**
    **File/section:** PLAN §§3.3, 5.1, 6.1; `databridge/.venv/Lib/site-packages/pptx/chart/data.py`, `CategoryChartData.add_series` (282), `categories` (297); `pptx/shapes/shapetree.py::add_chart`; `pptx/slide.py::notes_slide` and `notes_text_frame`.
    **Finding:** Native editable category charts, notes and BytesIO are supported. An in-memory probe created and reopened eight chart slides, each with three 12-point series, at 98,295 bytes; the 2 MB cap is plausible, not a demonstrated blocker. However, CategoryChartData has one shared category axis, whereas the proposed series may carry different x labels/orders after filtering. Positional insertion can silently assign values to the wrong label. Percent values are percentage points (0.35), so ordinary Excel percentage formatting would display 35%. Slides permit timeline charts, but the PPTX instructions cover only bar/line. Parseable line dates are not necessarily sorted. Maximum text/source lists can overflow a slide even in a tiny file.
    **Fix:** Align series by a canonical category key and use blanks, never invented zeros, for missing points; reject duplicates and sort chronological lines. Use a literal-percent display format or a clearly documented renderer-only scale. Define timeline export or exclude it from slides. Add layout budgets/continuation slides and a real visual opening check when implementation is authorized. Treat the size probe as evidence only for its fixture, not worst-case validation.

13. **Medium — Deterministic fallback parsing and bounds are underspecified.**
    **File/section:** PLAN §§3.3, 4.4 and 5.2; `databridge/fixtures/enterprise/world.json:4812`; `databridge/apps/internal_brain/databridge_ib/actions.py`, `split_facts` and `MAX_FACTS`.
    **Finding:** Equal comma counts are not CSV structure: quoted commas, embedded newlines and thousands separators break the detector. Conversely, arbitrary prose with commas can look like a block. The source-table path promises verbatim cells but does not define behavior for more than six columns, long cells or headers, or partial rows at the excerpt boundary. The quoted-facts fallback can exceed the 200-character cell cap because `split_facts` limits count, not length. Deterministic output also needs the injection/text checks; bypassing them would undermine T6.
    **Fix:** Parse intact candidate blocks with `csv.reader`, validate rectangular rows and bounds, and carry actual source-row provenance. Reject or explicitly truncate at safe row boundaries with clear disclosure. Apply a defined verification policy to deterministic output too; do not silently relax schema limits.

14. **Medium — PowerPoint installation is missing from the deployment dependency path.**
    **File/section:** PLAN §6.1 dependency and §9 step 7; `databridge/requirements-lock.txt`; `deploy/lighthouse/requirements-ib.txt`; `deploy/lighthouse/Dockerfile.ib` dependency COPY/RUN (19–21).
    **Finding:** PLAN correctly identifies missing python-pptx/XlsxWriter in the general lock file, and lxml/Pillow are already pinned there. But Lighthouse installs the separate trimmed `requirements-ib.txt`, which lacks the PPTX dependencies. Editing only the general lock does not enable exports in that image. The local installation is in `databridge/.venv`, not the repo-root `.venv`.
    **Fix:** Update both installation paths and their transitive pins if Slides ships. Verify a clean image/runtime import and export. Keep the proposed status capability and lazy-import fallback; missing dependencies must disable the button without breaking startup.

15. **Medium — The scheduled build time is arithmetically wrong and the cut is too late.**
    **File/section:** PLAN §9 build-order table, §8 T4/T5/T7, §10.2 presenter requirements.
    **Finding:** Listed steps total 230 minutes (3 h 50), not 210; steps 1–8 total 165 minutes, already beyond the 150-minute cut line. Slides export is built at step 7 before the decision to drop it. T4/T5/T7 require working export behavior but are scheduled before exports. The 30-minute integration-test allocation includes a paired-world matrix across every kind and both exports. Presenter hooks/recording are additional work in §10.2 without a clear build-table allocation.
    **Fix:** Decide scope at the start. Build schemas/evidence representation, verifier, minimal service/routes and CSV, then authorization/ledger/export integration tests, then a narrow UI. Defer Slides, timelines, multi-series charts, Analysis/Summary and presenter automation unless time remains. Keep the flag off until the complete safety slice passes; do not trade away T1–T7 to meet the demo deadline.

16. **Low — Content-Disposition strategy is safe only if the ASCII contract stays explicit.**
    **File/section:** PLAN §§3.1, 3.4, 6.3; `databridge/apps/internal_brain_web/app/api/ib/[...path]/route.ts`, `handle` response branches; `databridge/apps/internal_brain/databridge_ib/pipeline.py::ask` (107); `actions.py::ID_RE`.
    **Finding:** The live proxy already buffers bytes with `arrayBuffer()`, so binary delivery needs no text conversion. Its proposed exact attachment allowlist is a good constrained change. Pipeline-generated request IDs are UUID hex, but request/context validation permits broader strings; filename construction must not assume every accepted historical ID is hex. The regex intentionally rejects non-ASCII filenames and `filename*=` parameters. That is correct for fixed ASCII names, not a Unicode download implementation. Mock mode copies nearly all headers and bypasses the live relay logic, so mock download tests cannot validate production filtering.
    **Fix:** Emit the exact quoted ASCII filename on successful exports only; use a server-generated hex identifier or a safe fixed fallback for incompatible IDs. Relay only for the exact export path and a successful file response, with a client fallback name if the header is absent. Keep Unicode names out of scope; if later supported, specify an ASCII fallback plus encoded `filename*` and a matching parser deliberately. Test the live proxy against a stub upstream, including CR/LF, extra parameters, non-ASCII, duplicate headers and error responses. Retain no-store and POST same-origin checks.

## Missing tests

- **Version and race tests:** old answer/current source mismatch; multi-tag sentence provenance; drift during a blocked model call and between creation/export; revocation of one dependency from a multi-tag item; removal from derived titles/notes; compare emitted versions and timestamps. (PLAN §§4–6; `actions.py::context`, `authz.py::_snapshot`.)
- **Adversarial numeric tests:** `35%` inside `0.35%`, `20` inside `20000`, `20k` with value 20, accounting negatives, Unicode minus/full-width characters, malformed/locale grouping, lowercase flush currency, wrong metric or currency on the same row, hours as days, cross-series units, NaN/infinity/bool and duplicate categories. (PLAN §5; `value_forms.py`.)
- **Schema/fallback tests:** filtered objects below minima, ragged rows, overlong deterministic cells, quoted-comma CSV, excerpt cuts, empty labels, timeline misbinding/order, no-model count semantics, initial/lowercase/Chinese unsupported names. (PLAN §§3.3–5; `unsupported_named_terms`.)
- **Endpoint/store tests:** unauthenticated/inactive users on both routes; foreign-ID wrong-format indistinguishability; feature-off export; expired/evicted IDs; concurrent access; failed-created entries cannot export; partial export cannot mutate the sealed spec; canonical response digest. (PLAN §§3–4, 7; `app.py::principal_dependency`.)
- **Deadline tests:** queued work, hung backend, retry exhaustion, no late publication, no fallback starting after the deadline and bounded admission. (PLAN §4.2; harness `complete_structured`.)
- **Export tests:** native chart category/value alignment, literal percent display, embedded workbook formulas/external links, notes and source pruning, maximum text layouts, CSV cap and formula-leading whitespace/control variants, clean-install dependencies. Compare chart/workbook data as well as slide text in paired-world T5. (PLAN §§6, 8; installed `pptx/chart/xlsx.py`.)
- **Live-proxy tests:** attachment filtering and binary round trip through the non-mock branch, ASCII/Unicode/`filename*` handling, malicious or missing headers, error responses and slot b/c denial. (PLAN §3.1; proxy `handle`.)

## Feasibility verdict

**Hypothesis based on the observed scope:** the full plan is not credible within 3.5 hours with its promised validation; its own allocations require 3 h 50 before correcting the verifier, resolving provenance and chart semantics, or adding integration time. A narrower Table + CSV slice, with an optional single-series bar chart after the verifier passes, is plausible in 3.5 hours for someone familiar with this repository. Reusing ActionService ownership/authz, the real harness structured signature and existing native-chart APIs is feasible, but those helpers do not supply the missing evidence binding, publication lifecycle or export contracts. Commit to the reduced slice before implementation, put schema/evidence rules before verifier code, and test authorization, version drift and ledger failure before enabling the feature.
