# correspondence -- RFC 5322 mailbox extract

> SYNTHETIC FIXTURE. Generated by `../generate.py`. Every address is on a
> `.example` domain and routes nowhere. No real person wrote any of this.

200 messages under `<year>/`, in threads linked by
`In-Reply-To` / `References`, between the agency, applicants, claimants and
third parties (architects, contractors, an advocacy service, another
agency).

Bodies come in three shapes so every parsing path is exercised:

* `text/plain` -- the majority;
* `multipart/alternative` with an HTML alternative;
* `multipart/mixed` with a JSON attachment.

## Pinning

A mailbox is **T1 at best**: a monotonic history cursor replays forward
only and expires, so a past state cannot be reconstructed from the live
source. Because anything ledger-bound is captured, an `email_part` pointer
resolves against the **Capture Store**, never against the mailbox, and its
best possible verdict is `VERIFIED_AS_OF_CAPTURE`.

## Hostile content

This corpus contains **planted prompt-injection attempts**. They are here
on purpose: the trust layer has to be testable against real hostile text in
an otherwise ordinary mailbox. The answer key -- what was planted, where,
and what the system is supposed to do about it -- is `INJECTIONS.md`.

`INDEX.csv` deliberately does **not** flag which messages are hostile.
